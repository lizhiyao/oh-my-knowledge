=== 小结 ===
✅ 成功路径:run() return value 自动序列化,structured,exit=0
✅ this.log 在 --json 模式被 oclif 静默压制,stdout 只有 JSON,stderr 空
⚠️  失败路径(this.error 走 oclif):exit code 在,但 message 丢失,
   agent 调用方拿不到 reason 得 parse stderr
❌ 校验错误(parse fail):--json 触发整个 oclif Config dump,verbose + 信息泄漏面
   (cacheDir / configDir / home / pjson 全文)
→ 生产化需要 ~30-50 LOC 自写 jsonResponse() helper:
  - this.error 替换成 throw { code, message } 让 oclif --json 包成 clean error
  - parse error 在 catch 里 sanitize,只 emit { code: 'BAD_FLAG', message: '...' }
