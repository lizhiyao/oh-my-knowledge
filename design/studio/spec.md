# Studio 代表页原型与目标规范

本文件是 [Issue #1060](https://github.com/lizhiyao/oh-my-knowledge/issues/1060) 的设计评审正文，与同目录的静态原型一起构成协作者可访问的评审资产。它不是产品规范：当前实现基线以仓库根 [DESIGN.md](../../DESIGN.md) 为准，本文件只写「目标规范与依据」，并明确标出哪些是实测结论、哪些是待评审提案。

## 一、这套稿子证明什么，不证明什么

证明：

- 四张代表页（对话阅读、记录比较、候选与原文核对、报告详情）在目标 token 下的构图、阅读层级与信息密度；
- 按钮、链接、输入框、导航、表格、证据提示在默认／悬停／按下／焦点／禁用／加载六态下的取值；
- 空态、错误态、来源不可读、证据不完整、多来源、超长内容各自的呈现出口；
- 桌面与窄屏、较矮窗口下的布局边界，以及文字对比度、省略可达性、键盘焦点顺序的实测数值。

不证明：

- 任何功能已实现。原型不接入 Studio 构建、不参与打包、不是渲染路径；`src/studio/AGENTS.md` 明确产品页面只向 Next.js 收敛，本目录不推翻它。
- 精确像素或真实数据形状。全部为合成数据。
- 真实组件与 Ant Design 控件的实际渲染结果，也不等于屏幕阅读器实测。
- 目标规范已生效。落地要另行改主题与样式，并同步 DESIGN.md。

## 二、取证方法

```sh
sh design/studio/run-audit.sh                       # 六个视口 × 两套规范档 × 六个页面
node design/studio/audit-summary.mjs <输出目录>      # 打印结论表与未达 AA 的文字对
```

脚本用本机 Chrome 无头模式按精确视口加载页面，页面内 `audit.js` 在 `load` 后把实测 JSON 写进 `<pre id="audit-report">`，再由 `audit-summary.mjs` 解析。因此对比度、溢出、裁切、省略可达性都是浏览器计算样式的结果，不是人工声明。

局限：`--dump-dom` 不产图，所以本目录不用截图作证；`:hover`／`:active`／`:focus-visible` 无法由脚本触发，`states.html` 用静态复现类把六态并排画出来，复现声明与 `base.css` 的伪类声明一一对应，但真实交互反馈仍需人工在浏览器里确认。

## 三、目标规范

### 3.1 颜色

品牌紫作为填充与作为文字必须分开。实测：

| 前景 | 背景 | 对比度 | 12–14px 小字（需 4.5:1） |
|---|---|---|---|
| `#7753FF` | `#FFFFFF` | 4.70 | 通过 |
| `#7753FF` | `#F7F8FB`（应用底色） | 4.43 | 不通过 |
| `#7753FF` | `#F2EEFF`（选中底） | 4.13 | 不通过 |
| `#FFFFFF` | `#7753FF`（主按钮） | 4.70 | 通过 |
| `#5A3CDB` | `#F7F8FB` | 6.37 | 通过 |
| `#5A3CDB` | `#F2EEFF` | 5.94 | 通过 |
| `#5A3CDB` | `#FBEAE8` | 5.81 | 通过 |

结论：#1060 原文「主按钮与正文链接采用 `#7753FF`」在纯白之外都不达标，AA 的大字豁免要 24px（或 18.66px 粗体），正文与元信息都够不到。目标规范因此拆成两个 token：`--studio-action`（`#7753FF`）只做按钮等填充，`--studio-action-ink`（`#5A3CDB`）做正文链接与品牌色文字。**这一拆分与 Issue 原文不一致，是待评审项**；不接受拆分的替代方案是把所有品牌紫文字升到 24px，那会破坏密度。

状态色的墨度也要动。基线 `--tone-success-ink #1f9d63`、`--tone-warning-ink #d97706`、`--tone-neutral-ink #8893a5` 在白底分别只有 3.46、3.19、3.10，作为 12px 状态文字全部不达标；DESIGN.md 已把「小字号状态文字的对比度需在实际表面上验证」列为待收敛，这里就是它的结果：

| 角色 | 基线 | 目标 | 目标在白底 | 目标在自身 fill |
|---|---|---|---|---|
| 成功 | `#1F9D63` | `#14795A` | 5.37 | 4.74（`#E6F4EE`） |
| 警告 | `#D97706` | `#A1560B` | 5.45 | 4.90（`#FDF1E3`） |
| 错误 | `#DC2626` | `#B42318` | 6.57 | 5.65（`#FBEAE8`） |
| 中性 | `#8893a5` | `#5F6B7F` | 5.39 | 4.73（`#EEF0F6`） |

变深是必要的，但会让「成功」看起来不那么鲜亮——观感取舍需要评审确认。基线值保留在 `[data-spec="baseline"]` 档，切换即可对照。

其余口径：白色与浅中性底是主要表面；层级靠字号、间距、对齐和分隔线建立，不靠重复卡片；阴影只给覆盖层（窄屏侧栏 `0 0 24px rgba(25,34,54,.18)` 沿用现值）。

### 3.2 字体、间距、圆角与边界

- 字号按角色命名，不引入全站 display 阶梯：页标题 20/28、区段标题 16/22、正文 14/22、对话阅读 15/27、元信息 12/18。对话阅读从基线 14/1.8 升到 15/27，页标题从各页散落的 18px、22px 收敛为 20px——后者是提案，DESIGN.md 明确 22–24px 试稿未生效。
- 等宽只用于代码、技术标识与原始记录，并统一 `font-variant-numeric: tabular-nums`。全站当前没有任何 `tabular-nums`（`studio.css` 无此声明），所以数字对齐属于目标新增，不是既有事实。
- 间距取 4/8/12/16/20/24/32；圆角控件 6px、容器 8px、浮层 10px；结构边界一律 1px，焦点轮廓 2px 外偏移 2px（基线侧栏用内偏移 -2px，目标统一为 +2px，需评审确认不与 Ant Design 焦点环冲突）。
- 图标规范先钉**网格与描边**，不钉具体字形：16×16 视口、图形占 12×12 安全区（四周各 2px）、描边 1.5px、端点与折角 round、`stroke: currentColor`、`fill: none`。行内 14px 只用于正文中的小图标；导航、按钮、表头一律 16px。图标颜色随所在组件的文字色走，不单独指定，禁用时随文字一起变灰。状态不得只靠图标表达——图标旁必须有文字或 `aria-label`；成功／警告／错误也不得只靠图标形状区分，颜色之外还要有文字。具体字形待定：现有实现取自 Ant Design Icons，是否换自绘线性图标属实现决策；本目录原型里的字形是占位。

### 3.3 组件基元

`base.css` 是唯一实现：外壳 `.shell`／`.sidebar`／`.main`、页头 `.page-head`、内容区 `.page-body`、按钮 `.btn`（primary／默认／quiet × 六态）、链接 `.link`、输入 `.input`／`.select`、分段导航 `.tabs`、表格 `.table-wrap`＋`.table-scroll`、双行列表 `.list-row`（56px）、状态徽标 `.chip`、证据提示 `.evidence`（默认／partial／missing／unknown 斜纹）、折叠 `.disclosure`、三栏 `.panes`、异常块 `.state`、骨架 `.skeleton`、浮层 `.overlay`。

三条硬规则：主按钮纯色，不加渐变；选中底 `#F2EEFF` 上文字用墨色，不用品牌紫（见 3.1）；加载态保留按钮尺寸与标签，用 spinner 替换图标而不是隐藏文字。

一条派生规则：任何可能落在着色表面（选中底、fill、悬停底）上的文字，一律取 `--studio-ink-muted` 而不是 `--studio-ink-secondary`。元信息与安静按钮都实测踩过这条——`#657085` 在 `#F2EEFF` 上只有 4.38:1，`#5F6B7F` 为 4.74:1。

### 3.4 状态矩阵暴露的规范空洞与处理

`states.html` 把六态并排画出来后，暴露出目标规范本身缺的声明。这些不是 bug 清单，是规范空洞。逐项处理如下：

已在 `base.css` 补出定义（矩阵页同时补了静态复现格，可评审）：

- 安静按钮 `:active`：改为加深中性底、断开描边继承。此前它继承主按钮的紫色描边，按下看起来像被选中，语义上不是。
- 链接禁用（`aria-disabled`）与加载（`data-loading`）：禁用变灰且不划线；加载保留标签文字，在其后追加 spinner——与按钮同一口径，不隐藏文字。
- 一级导航、双行列表行、侧栏工作区行的按下档：只加深中性底 `--studio-surface-press`，不改文字层级；当前项按下仍保持选中底，不被悬停档压浅。
- 分段导航按下：文字升为主文字、下边框转墨色；选中项按下保持品牌紫。
- 表格行与列表行禁用：文字与底色一起降档，且悬停不再加深，避免「灰着但会响应悬停」的误导；两者共用同一取值，同一件事不该有两种灰法。
- 表头排序按钮 `.th-sort`：补出悬停、按下、键盘焦点（内偏移 -2px，避开 `.table-wrap` 的 `overflow: hidden` 对焦点环的裁切）、不可排序列的禁用档与当前排序列的强调色。加载档判为不适用——排序是同步行为，不触发异步工作。`measure.html` 里那份页内副本应在落地时删掉，统一到组件层。
- 异步下拉与文本输入的加载档（`data-loading`）：保留标签与尺寸，右侧指示并声明 `aria-busy`；两者同一口径，不给下拉特例。
- 行级加载（表格行、双行列表行、侧栏工作区行）：整行内容隐去、以骨架条替代但**保留行高**，避免加载时列表跳动；轮询期间的「结果区」骨架是页面级 `.skeleton` 的职责，不是控件自己的加载档。

明确「不适用」，不造没有语义的样式（这是规范决定，不是遗漏）：

- 一级导航与分区导航无禁用态：Studio 的四条泳道始终可达，不存在被灰掉的目的地。
- 导航无加载态：导航不触发异步工作，跳转即完成。
- 输入框无独立按下态：聚焦即按下，再画一档只会与焦点环打架。

仍需人工确认，未在本轮定稿：

- **加载指示在四类表面上不一致**：按钮用 spinner 替换标签、链接在标签前追加 spinner、输入与下拉是一条静态内嵌条、行级加载是骨架条。四处都能自洽，但放在一起就是四种语言。是否统一成一套（以及输入类要不要也转圈）需要评审定，本稿没有替它选。
- 真实 Ant Design 控件的焦点环与本目录自定义 `outline` 的覆盖顺序，未在真实组件上验过；落地时以实际渲染为准。
- 危险按钮是否成为规范组件（见第五节，三域当前都不存在）。

### 3.5 状态与证据语义

「运行完成」「证据完整」「结论成立」是三条独立轴，稿件与实现都不得合并成单一健康色。实测中最有说服力的构图是 `已完成 + 部分缺失 + 证据不足` 同时出现的那一行：它只能是中性/警告/警告，不能整体显示为成功。候选的「保留」同理——`保留表示愿意维护，不等于内容已得到证实。` 必须紧邻主操作出现。

状态取值一律来自现有枚举，不新增：运行状态 `已完成|已取消|预算耗尽|失败`；证据状态 `完整|部分缺失|无法解析`；结论状态 `可形成结论|证据不足|未评估`（`src/eval-core/contracts/artifacts.ts:467-471`，中文 owner `src/studio/web/components/measure/measure.tsx:97-103`）；维护状态 `已保留|已舍弃|待处理`（`src/studio/application/knowledge/candidate-status.ts:6-9`）。判定词 `PROGRESS`/`REGRESSION`/`NOISE` 由 Core 拥有、Studio 原样呈现，原型保持不本地化。

## 四、布局与响应式

断点提案：**1440 / 1280 / 1024 / 860 / 720**，替换现散落的 700／760／1100（DESIGN.md 的待收敛项）。

- ≥1280：知识核对为三栏（候选 220–260 / 陈述 自适应 / 原文 260–340）。
- 1024–1279：第三栏降为整行、限高 320px，仍与陈述同屏可见。
- 860–1023：三栏退化为单栏堆叠，原文核对改为按需详情；侧栏收窄到 224px。
- ≤859：侧栏变 280px 覆盖层，页头露出「打开导航侧栏」按钮（`nav-drawer.js`：点击开、Esc 与遮罩关、关闭后焦点回到按钮）；页头纵向堆叠；对话轮次取消左序号栏。此前原型只画了覆盖层却没有开关，等于窄屏下分区导航不可达，现已补成可点。
- 高度 ≤720：各栏最大高度收紧，保证页头与操作不被挤出。

取证视口刻意取断点两侧成对出现（1280／1279、1024／1023），避免「恰好落在某一档」的假通过。

内部滚动只允许出现在：表格 `.table-scroll`、长代码块、证据面板、侧栏工作区列表、浮层面板。全部带 `overscroll-behavior: contain`，实测各视口 `documentOverflowX/Y = 0`，即滚动不传播到页面。

长标识可达：省略单元格一律带完整内容出口（`title` 或详情入口），实测「省略无出口 = 0」。64 位摘要与含中文的长 runId 在 220px 列宽下被省略，展开路径是详情浮层而不是换行——表格不换行的领域规则保持不动。

## 六、三张代表页的取舍记录

**Observe 对话阅读。** 选择：正文 15/27 优先，轮次序号与时间压到 44px 左栏并降为元信息；工具调用收进折叠块，明细只给「查看执行详情」一个出口；不可读轮次用告警块而不是留白。放弃：竖向时间轴（占宽，窄屏最先被牺牲，且与现有 `reader.tsx` 结构对不上）；在列表内直接渲染调用明细（现有实现刻意不做，明细属于轨迹页）；把 Markdown 渲染成富文本（当前正文是 `white-space: pre-wrap` 纯文本，标记直显是 DESIGN.md 的待收敛项，稿子不假设已有渲染器）。待评审：阅读列宽 860px 是否够，跨轮对照是否需要双栏并读。

**Measure 记录比较。** 选择：连续表格 + sticky 表头 + 表格内横向滚动；三条状态轴并列成三个独立列；创建时间保持默认排序。放弃：卡片化列表（比较任务要求列对齐与扫读）；新增分数／指标列（列表 VM 无这些字段，画出来就是新统计口径）；把三条状态轴合并为一个「健康」徽标（会掩盖 `已完成 + 部分缺失`）。待评审：九列在 1024px 下横向滚动是否可接受，还是应把 `产物集摘要`／`报告 ID` 收进详情。

**Knowledge 候选与原文核对。** 选择：沿用已存在的三栏；原文高亮用 `<mark>` 加下沿描边；多来源共享一个证据片段选择器（现状如此，不画逐来源标签页）；主操作层级为 保留／舍弃 主、修订 次。放弃：把原文并进陈述栏（核对必须并置）；给「保留」加成功色（维护选择不是验证结果）。待评审：1024–1279px 下第三栏降为整行限高，还是直接改按需详情。

**报告详情。** 选择：顶部摘要带把三条状态轴与结果摘要并列，让「不可判断」和「已完成」同等醒目；左栏决策／比较条件／结论限制，右栏证据入口与阶段覆盖；保留 Tab 行以不破坏现有习惯。四个补齐层级各自标注真实来源与缺口性质（见第五节）。放弃：用绿色整体表示运行成功；把 `PROGRESS` 等判定词翻译成中文（Core 拥有词表）。

## 七、实测结论

取证环境：本机 Google Chrome 153 无头模式，`--window-size` 精确视口，`--dump-dom` 读回页面内 `audit.js` 在 `load` 后写入的 JSON。视口取 1440×900、1280×800、1279×800、1024×768、1023×768、860×900、720×640、1440×620（较矮窗口）——1280／1279 与 1024／1023 成对取断点两侧，避免「恰好落在某一档」的假通过；页面取 `index`／`observe`／`measure`／`knowledge`／`report`／`states`，规范档取目标与基线，共 96 个组合。

| 指标 | 目标规范档（48 组合） | 基线规范档（48 组合） |
|---|---|---|
| 页面级横向溢出 | 全部 0 | 全部 0 |
| 页面级纵向溢出 | 全部 0 | 全部 0 |
| 被裁切且不可达的滚动区 | 0 | 0 |
| 未达 WCAG AA 的文字对（去重后） | **0** | **74** |
| 省略但无完整内容出口的单元格 | 0 | 0 |
| 键盘可聚焦元素数（各页，1440×900） | 11／27／33／40／29／110 | 同左（结构与目标档一致） |

目标档另有 20 个未达但对比值被记为豁免（`states.html` 19、`knowledge.html` 1）：屏幕阅读器专用文字（`.sr-only`）、加载态刻意透明或隐去的文字、禁用态文字（`--studio-*-disabled`）与骨架。豁免理由由页面实际计算样式判定，不是人工归类；`states.html` 里这些格子仍画出来，供人确认它们确实不可见或确属禁用。

### 7.1 数值之外还看过一次渲染图

脚本量不出「构图有没有被挤到首屏之外」。用同一台 Chrome 出图逐页看过之后，发现一处真实缺陷并已修掉：页级评审注记（那段以「合成数据」开头的口径说明）在四张代表页上都是十来行长文，展开时把被评审的构图整段推到 1440×900 首屏之外——知识页的三栏核对、评测页的表格都看不到。现在注记默认收起为一行（`<details>`，一点即开），三栏构图回到首屏；就地标注的缺口说明（报告页的四层缺口、矩阵页的口径说明）**保持展开**，因为那是要评的内容而不是前言。矩阵页的注记一段都没收起，它没有页级前言。

同一次看图还确认了两件脚本判不了的事：高亮、虚线徽标、指示条在真实渲染下都成立；图标与指示条属非文本对比（WCAG 1.4.11），自测脚本只遍历文字节点，仍需人工核对。

仍未解决、需要评审判断的一处：知识页在收起注记后，`保留／舍弃／修订` 主操作行仍在首屏之下（陈述栏的事实表较长）。是把事实表收进按需详情，还是把操作行提到陈述标题之下，属构图取舍，没有替你选。

基线档的 74 个未达项集中在三处，正是第三节换值的依据：状态色 12px 文字（`#1F9D63`／`#D97706`／`#8893A5` 在各自 fill 上 2.7–3.2:1）、次级文字落在浅紫选中底上（4.38:1）、以及品牌紫文字在非纯白表面上（4.43:1）。这三处不是理论担忧，是量出来的。

未由本轮取证覆盖：`:hover`／`:active`／`:focus-visible` 的真实触发（以静态复现格代替）、焦点陷阱与 `Esc` 的实际焦点行为、屏幕阅读器、真实字体与中文换行。原先列在这里的两项已经补上并重新量过：断点两侧（1279／1280、1023／1024）已进入视口列表，窄屏侧栏抽屉做出了可用开关（点击开、Esc 与遮罩关、焦点回到按钮），96 个组合页面级零溢出。


## 八、实现任务拆分

每项都可独立验收，顺序即依赖顺序；除 8、9、10 外都不新增能力。

1. **token 落地**：把 `tokens.css` 的 `--studio-*` 迁入 `StudioTheme` 与 `studio.css`，页面不再硬编码。验收：改一个 token 能同时改变主按钮与链接；基线与目标可对照。〔部分完成：配色、页级字号、两档圆角已迁入并由 `test/architecture/studio-color-tokens.test.ts`、`studio-type-scale.test.ts` 钉住；间距、边界、断点尚未接入。〕
2. **品牌紫填充／文字拆分**：`--studio-action` 与 `--studio-action-ink` 分别接按钮与链接。验收：12px 链接在 `#F7F8FB`、`#F2EEFF`、`#FBEAE8` 上均 ≥4.5:1。〔已完成，PR #1067。〕

4. **侧栏选中态统一**：`#F2EEFF` + 墨色文字 + 2px 指示条，替换现 `#EEF0F6`。验收：一级导航、候选列表、运行行三处选中色一致，且选中底上无品牌紫文字。〔已完成，PR #1067；本批另把悬停档从选中底里分出来，四处悬停底色统一到 `#F4F6FA`，`#EEF0F6` 只留给人消息气泡；链接与主按钮的悬停深色收在主题的 `colorLinkHover`／`Button.colorPrimaryHover`，替换掉 antd 派生的浅紫（实测 2.42 与 3.08:1）。〕

9. **比较条件投影**：comparability 契约进 view-model。前置：确认「对照／处理」措辞与是否只读呈现。
