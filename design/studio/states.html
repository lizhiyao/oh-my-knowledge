运行量测

怎么读这张稿子：列固定为 默认 / 悬停 / 按下 / 焦点 / 禁用 / 加载。悬停、按下、焦点三列由 .state-preview[data-state="hover|active|focus"] 静态复刻 base.css 的伪类声明，所以能整列截图、能并排比对；禁用与加载走 disabled／aria-disabled／ data-loading／aria-sort 属性， base.css 的规则直接命中格子里的真实标记。每份矩阵都带 data-audit-contrast，包括禁用格：数字由 audit.js 在渲染后的计算样式上量出来，不由人填。

格子有三种口径，分开读：① 真实标记＝base.css 已定义这一档； ② 实线灰底格（.cell-na）＝规范判定这一档 不适用，格子里写着判定理由，这是决定不是遗漏，不为它造样式 （见 spec.md 3.4）；③ 虚线格 （.cell-todo）＝规范仍缺定义，待补。本轮把 ① 扩到安静按钮按下、 链接禁用与加载、一级导航／分区导航／双行列表行的按下、文本输入／搜索／下拉的加载、 表格行与列表行的禁用、行级加载、表头排序的悬停与焦点；把导航的禁用与加载、输入框的按下改判为 ②。 本页 ③ 已清零：表头排序按钮的按下与禁用（不可排序列）本轮补进 base.css， 加载档判为不适用——排序是同步行为，不触发异步工作；其余格子都已落到 ① 或 ②。 另两条未决项属人工确认，不是矩阵缺口（真实 Ant Design 焦点环的覆盖顺序、 危险按钮是否成为规范组件，见 spec.md 3.4 末尾）。

两处已知的量测噪声，先在这里说明，免得评审时误读：① 禁用态文字（--studio-ink-disabled／ --studio-action-disabled）按 WCAG 1.4.3 对禁用控件文本不设对比度要求， 脚本报红是预期结果，评审要判的是「这一档是否只用于禁用态」，不是把它拉亮； ② 非主按钮的加载态用 color: transparent 把标签让位给 spinner，文字节点本身没有前景色， 对比度不成立，属于组件层的设计选择，见第 1 节的待收敛说明；行级加载同理—— 列表行加载格的文字被 visibility: hidden 隐去、表格加载行的格子本来就是空的， 两处都不产生可见文字对（脚本给这类项的说明文字写的是 spinner，用在骨架条上措辞偏窄，属脚本侧待跟进）。 图标与指示条属非文本对比（WCAG 1.4.11），脚本只遍历文字节点，需要人工核对。

3. 输入框

这一列有两种结论，分开读。不适用：输入类控件没有独立的按下档—— 聚焦即按下，再画一档只会与焦点环打架（spec.md 3.4 的判定， 不是遗漏），所以按下三格改标为不适用，也不为它造样式。 本轮补齐：base.css 新增 .input[data-loading='true'] 与 .select[data-loading='true'] 同一条规则——保留标签与尺寸、描边降到 --studio-action-disabled、右侧给指示， 标记上同时声明 aria-busy；文本输入、搜索与下拉三格都换成真实标记， 不给下拉留特例。要分清的是：轮询期间进骨架的是结果区（页面级 .skeleton，真实用法见 observe.html 里进行中轮次的正文骨架），那不是控件自己的加载档。 焦点环与按钮不同：base.css 对 .input:focus-visible／.select:focus-visible 用内收偏移并加深描边，静态复刻时照抄同一批声明。

4. 导航

导航在六态之外多一档「当前／选中」，它决定读者在哪一页，不能塞回默认列。 本轮补齐：一级导航、分区导航与双行列表行的按下档 （base.css 新增 .nav-item:active、.tab:active、.list-row:active， 与 .side-row 同一组声明）——按下只加深中性底 --studio-surface-press，不改文字层级，也不把当前项染紫； 列表行的禁用与加载也一并补齐：.list-row[aria-disabled='true'] 与表格行共用同一取值（同一件事不该有两种灰法），加载走行级骨架 .list-row[data-loading='true']，整行内容隐去、以骨架条替代并保持行高。 悬停一档此前已按 Issue #1055 的口径补齐，本轮不动。 不适用（spec.md 3.4 的判定，不是缺定义）： 一级导航与分区导航没有禁用态——Studio 的四条泳道始终可达，不存在被灰掉的目的地； 导航也没有加载态——它不触发异步工作，跳转即完成。这两档写在格子里，不造样式。 三点提醒：① 当前页以背景块 + 指示条标识，且不参与悬停加深， 否则最深的一档反而变浅；② 矩阵目前没有 .side-row（侧栏工作区行）这一行，它的按下、禁用与加载取值与上面同一组， 进矩阵时再补格子，本轮不顺手加；③ 一格标不出两档， 「禁用＋悬停不加深」（.list-row[aria-disabled='true']:hover） 与「当前项＋按下」都要人工在浏览器里确认。 另有一处 base.css 与 spec.md 3.4 没对齐，如实标出不擅自补： spec.md 把「当前项按下仍保持选中底」写给一级导航、双行列表行与侧栏工作区行三者， base.css 这一条只写了 .nav-item[aria-current='page']:active 与 .side-row[aria-current='true']:active， .list-row[aria-current='true']:active 不在组里—— 按现在的源码顺序，选中的双行列表行按下会换成按下底而不是保持选中底。

5. 表格

表格的状态落在行上，所以这里按「一行一档」排布，禁用行与行内键盘焦点都是补进来的行： base.css 的 .table-wrap 带 overflow: hidden，贴边单元格里的焦点环可能被切掉，需要人工确认。 本轮新补的 .th-sort:focus-visible 用内收 -2px 的偏移避开这一裁切， 其余单元格里的焦点环仍按 --studio-focus-offset 外偏移，两种偏移的可见性都要人工判。 表头与单元格一律不换行；长标识单行省略并给出完整内容提示，或靠表格内部横向滚动看全， 不靠拆字适配列宽。空表行与上面的数据行互斥，同页只出现一种。

6. 证据提示

斜纹表面（--studio-tone-unknown-hatch）表示「不确定属于哪一档」，与「缺失」区分开：缺失是已知的坏，未知是还没判。不能拿它当默认值。

异常与边界

以下文案在产品里已有的部分逐字照抄，没有的部分按同一口径写清。空态、错误态与加载态 都要说明「现在能看到什么、下一步做什么」，不能用一片空白代替； 任何省略都必须留下完整内容路径，不能用 overflow: hidden 把内容或操作裁掉。

超长内容

规则：先靠紧凑布局、分页、标签页与按需详情分配空间；确有长内容的表格、时间轴、证据面板和抽屉 允许显式内部滚动，并约束高度、最小尺寸与滚动传播。任何一处都不得只靠 overflow: hidden 把内容或操作裁掉——省略号、内部滚动、详情入口三选一， 且必须让读者拿得到完整值。下面四例分别走这三条路径。

超长中文标题（30+ 字）· 路径：单行省略 + 完整标题提示 + 详情入口

当评委口径在修订层与文档层同时给出两种判据时，以决定产物字节的那一条为准并显式版本化 claude · 7 轮对话 · 悬停或聚焦时可见完整标题 阅读

标题被省略后仍然可达：title 给出全文，点进对话页读到全貌。

64 位 sha256 标识 · 路径：单行省略 + 全文提示 + 详情入口

2f8c41d9b63e47a0c5d18e2f97ab34c60d5e7f1a9b23c4d6e8f0123456789abc 打开该标识的评测详情

等宽 + 不换行：标识要能逐字核对，省略只发生在宽度不够时，且同时给出全文提示与详情入口。

200+ 字不换行长文本 · 路径：内部横向滚动（data-audit-region）

这条记录来自一次真实的规范讨论，参与者先争论判定口径应该落在修订层还是文档层，随后逐一核对哪些判据会改变产物字节、哪些只影响呈现，最后确认只把改变产物字节的那一条升格为测量语义并显式版本化，其余判据留在设计规范里由评审人工核对；整段文本是一行未换行的原始记录，横向滚动只是为了核对原文，不能因为容器宽度不足就把它裁掉或折叠成无法访问的内容。这也是本页把超长内容单独列成一节的原因：任何一处省略都必须同时给出完整提示或详情入口，让读者能拿到完整字符串，而不只是看到一个好看的截断效果。

原始证据按原样呈现：不自动折行改写、不截断尾部，滚动条就是它应有的样子。
