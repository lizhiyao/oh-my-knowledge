组件状态矩阵与异常边界

按钮、链接、输入框、导航、表格、证据提示的六态并排；空态、错误态、来源不可读、 证据不完整、多来源与超长内容的真实文案。合成数据，不接入 Studio 运行时。

运行量测

怎么读这张稿子：列固定为 默认 / 悬停 / 按下 / 焦点 / 禁用 / 加载。悬停、按下、焦点三列由 .state-preview[data-state="hover|active|focus"] 静态复刻 base.css 的伪类声明，所以能整列截图、能并排比对；禁用与加载走 disabled／data-loading 属性，本来就是静态可复现的。 每份矩阵都带 data-audit-contrast，包括禁用格：数字由 audit.js 在渲染后的计算样式上量出来，不由人填。

两处已知的量测噪声，先在这里说明，免得评审时误读：① 禁用态文字（--studio-ink-disabled／ --studio-action-disabled）按 WCAG 1.4.3 对禁用控件文本不设对比度要求， 脚本报红是预期结果，评审要判的是「这一档是否只用于禁用态」，不是把它拉亮； ② 非主按钮的加载态用 color: transparent 把标签让位给 spinner，文字节点本身没有前景色， 对比度不成立，属于组件层的设计选择，见第 1 节的待收敛说明。 图标与指示条属非文本对比（WCAG 1.4.11），脚本只遍历文字节点，需要人工核对。

6. 证据提示

证据条说明的是「这条结论能核到什么程度」，与运行是否完成、结论是否成立无关： 运行完成、证据完整、结论成立是三个维度，不得合并成同一枚徽标，颜色复用不代表语义合并。 状态徽标用 .chip，限制说明用 .evidence， 两者同处一条记录但各自独立；说明性文字不靠颜色单独编码。

行＝证据状态，四档覆盖「能核到什么程度」的全部已知取值；未知不是「没有」，是「读不出是哪种」。

异常与边界

以下文案在产品里已有的部分逐字照抄，没有的部分按同一口径写清。空态、错误态与加载态 都要说明「现在能看到什么、下一步做什么」，不能用一片空白代替； 任何省略都必须留下完整内容路径，不能用 overflow: hidden 把内容或操作裁掉。

空态

对话列表

暂无对话记录。Agent 运行后记录会自动出现在这里，使用说明见“设置与帮助”。

虚线边框 + 无操作按钮：这一档不需要动作，读者等下一次运行即可。入口在侧栏「设置与帮助」，不在空态里重复造。

评测列表

尚无评测记录。运行 omk eval --control <baseline> --treatment <candidate> 完成一次评测，结果会显示在这里。

空态里给出可直接复制的命令；命令文本与前后句同一段落，不拆成两块让人自己拼。

搜索无匹配

没有匹配的记录

没有匹配的对话。搜索只匹配标题、路径与项目名，不检索消息正文。

「没有匹配」与「还没有数据」是两档，措辞和动作都不同：前者保留结果区并给清空入口，后者不给动作。表格内的空表行见第 5 节。

候选区空态（内容列）

选择候选，与原始记录逐条核对。

三栏核对的中间列在没选中候选时保持尺寸，不塌成一条，避免左右两栏横向跳动。

候选区空态（依据列）

选择一条陈述查看依据。

依据列在没选中陈述时与上一条同档；两句话不会同时出现在同一个已选中状态下。

错误态

读取后续对话失败

暂时无法读取更多对话，已加载内容仍可查看。

两个按钮不同时出现：读取游标已失效需要重来时给「重新读取对话」，否则给「重试」。已加载内容不清空、不灰化，失败只说明失败的那一段。

轮询失败

更新暂不可用

暂时无法获取新内容，当前列表仍可查看；系统会自动重试。

后台更新失败是轻提示，不用错误红底、不打断阅读；「会自动重试」必须写出来，否则读者以为列表坏了。产品里这里的重试走链接型（安静）按钮。

来源不可读

这一轮的原始记录读不出来，其余轮次仍可阅读。
查看执行详情

此来源不可用，不能核对完整证据。

原因码直接写给读者（source_missing 等），不翻译成含糊的「出错了」。产品里这一条是 warning 级提示，不是 error 级：来源不可读不等于评测失败，所以不进红底。快照仍在列表里，删除是显式操作，不因来源不可读自动发生。

超长内容

规则：先靠紧凑布局、分页、标签页与按需详情分配空间；确有长内容的表格、时间轴、证据面板和抽屉 允许显式内部滚动，并约束高度、最小尺寸与滚动传播。任何一处都不得只靠 overflow: hidden 把内容或操作裁掉——省略号、内部滚动、详情入口三选一， 且必须让读者拿得到完整值。下面四例分别走这三条路径。

超长中文标题（30+ 字）· 路径：单行省略 + 完整标题提示 + 详情入口

当评委口径在修订层与文档层同时给出两种判据时，以决定产物字节的那一条为准并显式版本化 claude · 7 轮对话 · 悬停或聚焦时可见完整标题 阅读

标题被省略后仍然可达：title 给出全文，点进对话页读到全貌。

64 位 sha256 标识 · 路径：单行省略 + 全文提示 + 详情入口

等宽 + 不换行：标识要能逐字核对，省略只发生在宽度不够时，且同时给出全文提示与详情入口。

200+ 字不换行长文本 · 路径：内部横向滚动（data-audit-region）

这条记录来自一次真实的规范讨论，参与者先争论判定口径应该落在修订层还是文档层，随后逐一核对哪些判据会改变产物字节、哪些只影响呈现，最后确认只把改变产物字节的那一条升格为测量语义并显式版本化，其余判据留在设计规范里由评审人工核对；整段文本是一行未换行的原始记录，横向滚动只是为了核对原文，不能因为容器宽度不足就把它裁掉或折叠成无法访问的内容。这也是本页把超长内容单独列成一节的原因：任何一处省略都必须同时给出完整提示或详情入口，让读者能拿到完整字符串，而不只是看到一个好看的截断效果。

原始证据按原样呈现：不自动折行改写、不截断尾部，滚动条就是它应有的样子。
