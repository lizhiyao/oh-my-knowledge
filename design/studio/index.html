在现有层级上补齐结果摘要、比较条件、证据入口与结论限制，并标注各自的真实数据来源。

按钮、链接、输入框、导航、表格、证据提示的六态，以及空态、错误态、来源不可读、证据不完整、多来源、超长内容。

怎么读这些稿子

  1. 用浏览器直接打开任意 .html，无需构建、无依赖。
  2. 顶栏的「目标／基线」切换同一份构图的两套 token：目标是 #1060 已确认方向，基线是现有实现提取值。切换不等于产品已改动。
  3. 访问 ?audit=1（或顶栏「量测报告」）读取本页的实测数据：文档是否溢出、各滚动区是否裁切、文字对比度、省略单元是否有完整内容路径、键盘焦点顺序。
  4. 命令行批量取证：在仓库根执行 sh design/studio/run-audit.sh，它用本机 Chrome 无头模式按精确视口跑一遍并把 JSON 落到临时目录。
  5. 任何看起来像新功能入口的东西，先在 spec.md 的入口映射表里查它对应哪个现有能力；查不到就说明它是缺口，不是承诺。

评审时需要你判断的

  • 三栏候选核对在 1280px 与 1024px 的退化方式是否可接受，还是应当改为两栏＋按需详情。
  • 报告详情的「比较条件」需要新的 Studio 投影，措辞（对照／处理）与是否本轮立项都未定。
  • 状态小字号文字改用更深的墨绿／墨橙／墨红后，观感是否仍可接受——这是为了让 12px 文字达到 4.5:1，基线色做不到。
  • 危险按钮在观测、评测、知识三域当前不存在，是否要作为规范组件补上。
