## 1. Versions and scope

Exact positions do not establish semantics or artifact identity. Recorded-output replay and authored responses verify representation, admission and review candidates, not new model effectiveness.

Current `test/fixtures/entity-extraction-review-v12.json` contains 60 public synthetic windows and 199 critical mentions: 58 development windows and two reserved validation windows. The frozen corpus owns complete-name alternatives, identities, knowledge roles and itemwise rationales. It is neither a hidden blind set nor representative real logs, and contains no real message text. Viewed output windows serve only as development regressions, without blind-gain claims. New validation windows must be grouped separately by project/conversation and determined before output, without informing prompt tuning. Real logs need separate minimization, authorization, grouping and review.

Raw byte digests of the prompt, corpus, both language guides, checker and runtime artifacts bind the measurement identity. Updating current documentation also changes guide digests in new review packages; regenerate and freeze those packages. Old outputs, annotations, strict failures and scores remain unchanged and are not rescored under current rules. Different measurement identities cannot be compared directly; their frozen originals remain traceable through the corresponding Git revision and issues/PRs.

That checker-v5 change itself did not alter the then-current prompt bytes or run format. Historical no-few-shot strict-v15/run-v5 evidence retains its separate prompt/wire/pipeline identity. Updating this guide also changes new preparation digests, so old pending plans must be prepared and frozen again before any newly authorized measurement; old runIds and execution permissions cannot authorize new v16 requests. ## 2. Annotation units and allowed expressions

Freeze source messages, roles, omitted records and window limitations before annotating each item:

| Annotation | Rule |
|---|---|
| Critical mention | Names and references needed for retrieval, identity or understanding knowledge, rather than every noun. Keep message index, verbatim quote and zero-based occurrence; count overlapping matches and use UTF-16 half-open spans. |
| Allowed boundary | `alternatives` lists equivalent boundaries agreed before outputs, such as a complete code identifier with or without backticks, or a short name and qualified description denoting the same object. An arbitrary broad quotation containing the name is not a hit; broader boundaries are review candidates. |
| Identity group | Mentions with the same `entityKey` must merge; different groups must remain separate. Model IDs and labels are not gold. Align source spans before comparing mention pairs. |
| Granularity and links | Annotate allowed `referentKinds`, identity status, explicit candidates, component and collection membership/completeness. Alternatives need prior agreement; uncertain sources retain uncertainty. |
| Knowledge roles | Annotate source anchor, subject, object and interpretation first. Relations may use synonymous wording. A human checks semantics, direction, negation, conditions, time and corrections against the full window; missing keywords are not errors. Declare `coverage: required` or `if_selected` before outputs. |

A collective reference is one collection mention, not duplicate member mentions at the same span. Instances/versions differ from their component; environmental conditions alone do not force new identities. Distinguish tools from logs, plans from executions, replacement from rename. Matching names or paths are insufficient to merge. Truncated sources do not automatically require empty knowledge: an unresolved subject may retain a source assertion and pending investigation, without filling missing identity or generalizing conclusions. If two identity schemes are reasonable, adjudicate first or explicitly allow alternatives before outputs; this contract does not encode conflicting identity partitions, so unresolved disputes cannot be frozen.

Mention boundaries follow object meaning under [identity rules section 2.3](./entity-identity.md), rather than minimizing string length. “当前 main 的被测代码” and “enabled 字段” still denote the same objects and can be listed before new measurement outputs; “main 上的改造” discusses a change property, so the code-state mention should select `main` inside it. Do not mechanically strip “字段”, “的” or “上的”, or accept any sentence containing a short name. The program still matches predeclared alternatives exactly, without automatic trimming or regex-based semantic judgment. Recompute occurrence when narrowing to a repeated short name: the second `main` has occurrence 1, regardless of the unique longer phrase.

Judge type evidence separately from identity resolution: names, calls, failures or “node” labels alone do not prove components/deployed instances. A known identity with unknown type stays proposed object with type uncertainty; explicit module roles or deployment instances must not be downgraded. Qualified descriptions and short names may be prefrozen alternatives, never widened after new outputs. Distinguish shared references from their properties: their/它们 refers to a collection; a property phrase cannot identify just one member. Read relation and polarity together without double negation; “not failed” does not mean “passed”, and “not prohibited” does not mean “required”. Per-case semantic criteria preserve these judgments without keyword classifiers.

Review ordinary objects, abstract concepts and named objects case by case, including whether descriptions faithfully explain contextual meanings. Semantic category is not referentKind: a concept and a particular object may both be object without sharing identity. A product named “Plan” is not necessarily a plan. Record omissions, false extractions and unsupported categories/meanings beyond critical mentions; incomplete annotation does not support overall precision/F1. Inspect entity coverage even with no knowledge proposals; empty knowledge alone does not establish reliable associations.

Retained itemwise semantic review checks that central concepts are not replaced by statistics/adaptation objects. Short concept spans may overlap complete compound-object spans, without duplicating the same span; words inside product names do not automatically become concepts. An assistant-selected answer is not user clarification: retain the original ambiguous mention as unresolved with same-level candidates (or empty candidates plus a reason when levels differ), and only reconsider earlier mentions upon explicit clarification. Each statement has one proposition with uniform modality/polarity. Separate positive/negative requirements and their citations; context cannot restrict a single negative polarity to the latter clause, and a collective predicate cannot be mechanically split into member facts. Itemwise review applies these standards; structural admission uses no keyword inference or result completion.

Granularity review checks both omissions and excessive splitting: determine whether the source describes properties/behavior of a thing or independently defines, compares, refers to or associates an object before choosing identity. Ordinary properties can be statements about their owner; independent metrics/operation concepts must not be collapsed merely because they involve statistics/processes. Missing proper names or knowledge candidates is not an exclusion rule. Values, units, conditions and unconfirmed outcomes remain in statements. Critical mention matches do not prove this boundary correct. Record extra entities, actual knowledge wording and absent optional knowledge case by case; self-review is not independent evidence. Never alter identity schemes after output.

Review modal negation against the source meaning. These are examples of equivalent expressions, not a keyword classifier:

| Source assertion | Allowed expression | Unsupported inference |
|---|---|---|
| No need to modify SDK | descriptive/negative, “needs modification”; negates necessity in this scenario. | Modification is prohibited or did not happen. |
| Should not modify SDK | normative/negative, “modify”. | Modification is unnecessary or the rule was followed. |
| SDK modification was not prohibited | descriptive/negative, “modification is prohibited”; negates prohibition status. | Explicit authorization, a requirement to modify or actual modification. |
| Explicitly allowed/prohibited SDK modification | permission/positive or negative, “modify”; retain authority and scope. | Permission in other scenarios or execution results. |

Reported requirements retain normative/permission modality with source_assertion evidence; context preserves speaker, conditions, time and scope. Descriptive statements can also retain source assertions, without becoming direct observations. Negated necessity/prohibition status requires that predicate in relation rather than reducing every relation to the action. Read “cannot modify” in context to distinguish incapability from prohibition. A context mentioning “no need” cannot repair a statement already expressing prohibition. Retain unknowns or omit statements when the meaning cannot be expressed unambiguously. Cite modalities and conditions separately; missing optional knowledge is not_observed, never a modality pass.

Branch/tested-state review follows [identity rules section 3.1](./entity-identity.md): distinguish branch objects from separately referable version states; missing SHAs do not imply unresolved identity. Freeze allowed levels first. Branch subjects still qualify this tested state/source time. Distinct commits stay separate; dates alone do not split branches. Unknown reproduction identifiers and unreleased status remain explicit.

Configuration review follows [identity rules section 2.2](./entity-identity.md): selected knowledge retains exact values, types, owners, scope, conditions, source reasoning, and unknowns affecting judgment/reuse. An existing owner may be the subject with field and value stated; field endpoint differences are only review cues. Description, qualifiers, or accessible quotations do not establish complete statements. Each role declares `coverage: required` for mandatory facts or `if_selected` for retention when selected. Missing critical values in related knowledge are information loss; absent optional knowledge is not_observed; absent mandatory facts are coverage gaps. These differ from entity omission. A `none` policy cannot contain required roles.

### 2.1 Itemwise complete-name audit

1. Read the source, identity group and every boundary for each existing critical mention. Audit the same occurrence rather than substituting another same-named mention elsewhere.
2. Consider type words, articles/demonstratives, owners, location and time qualifications; add only contiguous noun descriptions centered on the same referent. “已发布 r2”, “Its test instance `sieve/dev01`” and “昨天的更新活动 U1” can be qualified names. Stop before pass/failure/assignment predicates.
3. Check the phrase's actual head: “项目 Pavo 的 a.md” denotes the file and “客户端 L 的 errorStatus” the field, permitting overlap with shorter owner mentions. Neither entire phrase denotes its owner. Plural member lists are not individual names; Session counts are not aliases for Session.
4. Recompute occurrence and UTF-16 bounds independently for each added quote; preserve old alternatives, itemwise reasons and rejected examples. Matching stays exact, without accepting arbitrary containing spans or replacing review with suffix regexes.

The audit covers every existing critical mention, without claiming all possible synonymous/nested descriptions or annotating every noun. A newly discovered post-output gap retains that run's strict miss and stop, with repairs in an explicitly versioned revision. Recorded outputs only check coverage and excluded boundaries offline, never new model-quality evidence.

### 2.2 Critical-source targeted diagnostic v1

`test/fixtures/entity-source-coverage-v1.json` is a separate synthetic development case, `omk-entity-source-coverage/v1`: three messages, two objects, two identity mentions and five critical knowledge sources (purpose, current limit, applicability condition/exception, late-event constraint, and subsequent correction/unverified limit). It is not added to the 60-window corpus and does not change the critical-mention denominator.

Before a model diagnostic, freeze this window, exact critical source positions, required knowledge and allowed expressions, current prompt/Schema, runtime and dependency digests. Authorize the specific model, budget and transfer separately. Authored responses are not model outputs. Empty knowledge remains structurally valid but leaves the five predeclared obligations uncovered. Ordinary repeated names need not all be saved.

Review each item: whether its statement retains the judgment and conditions, constraints, exceptions and corrections; whether its directly located citation supports that statement; whether mention identities/rationales match actual locations; and whether plans, source assertions and unverified limits remain intact. A mention helps users locate text but does not replace a statement's critical citation. Access to the complete message, a broad quote containing keywords, identical endpoints or a citation attached to another statement do not automatically establish semantic coverage. Reusing critical checker v5 anchor/statement lists only provides review candidates; `semanticReview` remains pending.

The predeclared targeted threshold requires recorded planned calls without call/parse/structural failures, correct identities for both objects and itemwise author agreement on all five knowledge/source obligations. Stop on missing coverage, definite errors or annotation disputes. Missing independent evidence remains explicit. This threshold does not replace section 3's original critical regression threshold or establish overall quality/stability. Only authored-response regressions have completed: zero new model calls and unverified automatic extraction effectiveness.

## 3. Layered results and acceptance threshold

| Layer | Recorded checks | Limits |
|---|---|---|
| Calls and capture | Separate call failures, JSON parse failures, cancellation and unattempted items. | Internal checker exceptions stop the run instead of becoming model failures; no retries hide failures. |
| Structural admission | Envelope Schema rejection, rejected mentions/entities/proposals and itemized reasons. | Structural rejection of valid JSON is a captured output, never `capture_failures`. Rejected item counts include cascading consequences, not independent mistakes. |
| Critical mentions | Exact matches/missing/ambiguous mentions, broad-boundary candidates and critical mention recall. | Annotation is not exhaustive: precision/F1 are `null`; extra mentions need human review and are not automatically false positives. |
| Identity | Required same/different mention pairs, wrong merges/splits and granularity/candidate/component/member differences. | Unaligned mentions or missing references are `not_evaluable`, never passes. Correlated pair counts are not independent-sample accuracy. |
| Knowledge links | Statements linked to the source anchor, endpoints, relation, modality and polarity; reversed endpoints raise review prompts; no statement is `not_observed`. | Matching endpoints do not establish correct relations or truth. Other statements sharing an anchor, broad citations and synonyms require human review. |
| Knowledge coverage obligations | Each role preserves coverage, interpretation, and references to all accepted statements. Without structural rejection or knowledge candidates, required becomes `required_not_observed`, and if_selected becomes `not_observed`. Any candidates require `needs_review`; structural rejection yields `not_evaluable`. | Citation/endpoint matches do not establish values, types, owners, or reasoning; review alternate evidence/subjects against the full text, without keyword-based passing judgments. |
| Independent semantics | Per-case `semanticChecks` cover conditions, time, negation, assertions/observations, plans/completion, case organization and late corrections. | `optional` permits no knowledge; omission differs from error. Knowledge under `none` requires an issue. Empty results do not establish reliable knowledge links. |

Frozen synthetic critical regression threshold: every planned call has a record; no call/parse failure, cancellation, unattempted item or structural rejection; 100% critical mention matches; all same/different mention pairs and identity links match without `not_evaluable`; independent human review approves generated knowledge roles, conditions and status with no unresolved disputes. Omitted optional knowledge supports entity-only conclusions and leaves knowledge-link coverage insufficient. This tool never automatically declares the entire threshold passed: `semanticReview` stays `pending`, with unverified scope reported. Predeclared required facts need itemwise coverage confirmation; structural rejection does not establish semantic absence from lack of accepted knowledge.

This threshold covers specific boundaries, not overall quality. Two repeats supply at most two samples; passing both does not establish population stability or cross-Agent benefits. Real-log sampling and thresholds are separately predefined, never adjusted after seeing outcomes.

## 4. Independent review, disputes and freezing

1. The implementer/author checks semantics, source closure, positions, grouping and contracts case by case, recording rationales in `omk-entity-author-review/v1`. `authorReview: completed` and `exploratoryReady: true` support continued engineering and exploratory evaluation without requiring the user to review every case. Self-review supplies no independent human evidence; `goldReady` stays false. Missing independent review is a reported coverage limit, not a blocker for this work; the independent quality completion threshold is unchanged.
2. A person independent of the authors checks each case's guide, allowed boundaries, identity groups, roles and semantic criteria. Complete `review-template.json` with `approved` or `changes_requested` per case, rationale, reviewer, timestamp and independence declaration. An independent model judge does not equal independent human review.
3. Adjudicate disputes before seeing outputs, recording the question, resolution and independent adjudicator. Unresolved disputes use `changes_requested`. Corpus/guide/checker changes require a version change and new bundle; editing a receipt cannot approve a different digest.
4. Both author and independent records cover every case, bind the measurement identity and predate output capture. Either supplied record requesting changes makes both readiness flags false; self-review cannot override independent disagreement. The checker rejects author self-attestation, omissions, wrong digests and post-hoc approval. It checks record closure and declarations, not actual reviewer identity or judgment correctness; `attested_independent_human` is a declaration, not an effectiveness conclusion.
5. The measurement identity combines corpus, bilingual guide, compiled checker and production runtime digests, dependency manifest/lockfile digest, Node version, raw UTF-8 prompt digest and versions. Rebuilding changes identity if artifact bytes change; retain the frozen build for evaluation. The bundle preserves both original guide files and a combined reading copy. Runtime promptHash uses canonical JSON hashing rather than the raw UTF-8 digest here; do not interchange them.

## 5. Offline review tool and evidence

Update compiled artifacts, then prepare an external bundle:

```bash
yarn build:runtime
node dist-scripts/bench/entity-extraction-review.js \
  --corpus test/fixtures/entity-extraction-review-v12.json \
  --output /private/tmp/omk-entity-review-unique
```

The output must be absolute, outside the repository, with an existing parent and nonexistent destination; symlinks into the repository are rejected. It preserves raw corpus, bilingual guide, `review.html` with positions and annotations, review template, model inputs/digests and measurement manifest. Without an independent receipt, `goldReady: false` even after completed author review. The default template requests changes and has no signature; it cannot approve anything without completion.

Optional `--self-review /absolute/self-review.json` validates an author record (measurement identity, author, timestamp, per-case decisions and rationales) and saves `self-review.json`. It has no independence attestation and cannot pass as human evidence via `--review`. Optional `--review /absolute/review.json` validates an independent receipt; optional `--captures /absolute/captures.json` checks existing captures only. **No executor entry exists: this command makes zero model calls.** Preparing a bundle or signing annotations does not authorize data transmission or model execution.

Capture format `omk-entity-captures/v1` contains the same `measurementId`, one split, one or two planned repeats, start time, executor/model and records with `caseId`, repeat index, frozen input digest and result. Results are `output` (verbatim text and optional original usage), `call_failure` or `cancelled`, with optional executor-reported `durationMs` and `costUSD`; omit unknown values instead of inserting zero. Unknown, duplicate, excess and input-mismatched records are rejected. Raw captures and admission results remain intact. Unattempted records are itemized; unchecked critical mentions stay outside the matching denominator and have their own count. Aggregate only reported usage, duration and cost. Total cost is `unknown` if any recorded attempt lacks reported cost, while the reported subtotal remains visible; partial cost coverage is not the whole-run cost.

Structural rejections do not fail capture status; call/parse failures, cancellation or incomplete plans cause a nonzero exit. Successful exit only means offline inspection completed. Raw outputs, itemized admission, original usage and every failure remain available; semantic review stays pending. Captures approved only by the author are `exploratory_semantic_review_pending`, never an independent acceptance pass. Subsequent model evaluation runs only within concrete authorization and obtains itemized independent output review.
