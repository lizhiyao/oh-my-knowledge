# 选定记录中的实体提取

状态：#1119 已实现，当前只支持现行数据结构，不提供旧格式读取、恢复或迁移。[v2／v3 对照报告](../explanation/entity-extraction-quality.md)保留历史观测结果及一处待裁决的对象粒度问题。本文不把调研或结构校验视为模型效果证明。

## 1. 用户结果与范围

用户从选定记录核对「谈到了哪些对象、哪些提及指向同一对象、哪些无法确定」，并让多条知识引用共同的实体分析。实体包括人、文件、系统、规则、概念和计划；主体与对象是陈述中的角色。概念定义见[OMK 如何理解知识](../explanation/knowledge.md)。

首版范围是一份不可变来源窗口。名称相同、路径相同、类型相同或文字相似都不构成合并依据；不自动跨日志合并，不建立全局实体库或图推理。识别对象不证明关于它的陈述真实。

用户沿用「选择记录 → 提炼」入口。提炼结果与历史中可按需核对、纠正实体，零知识候选时也可查看实体。核对实体不成为每次提炼必须经过的独立步骤。

## 2. 调研与选择

| 一手来源 | 相关实践 | OMK 的选择 |
|---|---|---|
| [End-to-end Neural Coreference Resolution](https://aclanthology.org/D17-1018/)（2017） | 文本跨度与上下文支持提及及先行项判断。 | 保留提及位置和对应依据，代词不按最近名称机械归一。 |
| [GLiNER](https://aclanthology.org/2024.naacl-long.300/)（2024） | 开放类型的命名实体识别。 | 不限定实体类别；识别与身份消歧分别验收。暂不引入额外 Python 模型依赖。 |
| [实体级联合关系提取](https://aclanthology.org/2021.eacl-main.319/)（2021） | 联合利用局部提及、共指与实体级关系。 | 首选一次调用、独立结果；共享窗口实体目录，知识候选引用它。逻辑边界不强制两次调用。 |
| [GraphRAG Dataflow](https://microsoft.github.io/graphrag/index/default_dataflow/) | TextUnit 保留来源关联；实体与关系共同提取；默认按名称和类型合并。 | 保留来源关联；按名称和类型合并不适合 OMK 的同名对象边界，不照搬该策略或全图索引。 |
| [W3C Web Annotation](https://www.w3.org/TR/annotation-model/#text-quote-selector) | 原文短语及前后文帮助区分重复片段。 | 模型提供原文及紧邻上下文，宿主校验唯一位置。多个匹配仍拒绝，不任取第一处。 |
| [LLM 共指能力评测](https://aclanthology.org/2024.lrec-main.145/)（2024） | 用自动与人工分析考察不同提示词的优势和失败。 | 分开报告结构接纳与语义错误，采用输出前冻结的案例。 |
| [LEA 共指评测研究](https://aclanthology.org/P16-1060/)（2016） | 从实体链接考察共指评测口径。 | 单独检查应对应和必须分开的提及，避免只报实体数量或名称匹配。首版不声称实现完整 LEA 指标。 |

这些资料支持设计取舍，不能证明 OMK 日志上的提取效果。采用一次调用是当前架构选择，是否增加第二次调用须用固定模型、输入和复核标准比较收益、成本及失败。

## 3. 契约与身份

实体分析独立于知识候选，保存实体、提及、身份歧义与来源限制。模型仅使用窗口内的临时身份；宿主为整个分析分配一次 UUID，多条知识复用它。

- 提及保存原文、引用、UTF-16 位置、显式／推断类别和对应理由。
- 实体描述帮助识别对象，限定信息用于说明项目、版本和环境。实质知识进入有上下文与证据的陈述。
- 未消解提及对应一个局部未知对象，保留可能对象与不确定性；不能任选候选对象充当已确定身份。
- 每个实体至少有一个接纳的提及；提及、可能对象与知识陈述的引用必须闭合。空实体和空知识结果均合法。
- 模型短语可附紧邻前后文；宿主不做模糊匹配、不规范化原文、不信任模型提供的数字位置。OMK 沿用 UTF-16 位置，不声称使用完整 W3C 选择器协议。
- 部分拒绝逐项记录原因。无效提及不能支撑实体，无效实体不能支撑陈述；不静默修补或删除歧义后接纳。

## 4. 纠正与知识修订

实体分析拥有不可变修订、父修订、作者、时间及理由，修改采用 generation 与写入头检查，并保留幂等写入身份。用户可以改提及对应、拆分或合并局部对象、补充遗漏提及、删除误识别和保留歧义。已有提及身份不能被换到另一段原文；重新定位须另建提及。

知识 grounding 绑定明确的实体分析及修订。生成后的纠正不覆盖旧知识。用户将新分析用于知识时，核对各陈述的主体／对象和证据，另建知识修订。一个旧对象被拆成多个对象时，应用流程不任取一个作为新主体。

纠正仍是人或 Agent 的判断，不自动变成事实验证，也不继承旧知识修订的保留决定。来源删除或不可读取保持显式不可用，不能仅凭保存的引用声称重新核对过原文。

应用时默认保留原知识的附加身份不确定性，用户可明确核对和更新，原说明仍在旧修订中。当前实体分析中的不确定性强制带入，不能用空输入抹去未消解指代。陈述中的条件、例外和未知信息另在知识修订中核对，不根据改名或合并自动删除。

## 5. 领域与运行边界

`knowledge` 保存纯契约、引用和修订不变量。`observability/knowledge-extraction` 保存选定窗口、模型传输、接纳和应用流程；文件适配器实现存储。Studio 与 CLI 复用同一应用流程。Evaluation Core 不承担观测实体或文件系统副作用。

运行先持久化预约，再调用模型；原始输出及实际报告的用量先保存，再准备实体与知识写入意图。恢复使用已经分配的身份、当前 prompt 身份和幂等命令，不重新调用模型。实体提交在知识提交前完成；中途失败仍可继续保存未完成的知识意图。

提取只发送选定片段和覆盖限制；不发送原始路径，不按日志中的指令读取外部来源或调用工具。未报告成本表示未知，不能当作零。

## 6. 当前存储契约

`entities/<analysis-id>.json` 使用 `entity-analysis-history` v1，保存不可变实体修订、来源绑定及写入回执。`items/<identity-digest>.json` 使用 `knowledge-item-history` v2；本提取流程生成的知识 grounding 绑定明确的实体分析修订。

`runs/<run-id>.json` 使用 `knowledge-extraction-run` v3，仅支持 `knowledge-extraction-v3`，保存当前提示词身份、原始输出、准备好的实体／知识意图及用量。当前运行恢复复用已分配身份和幂等命令，不重新调用模型。

这是 `BREAKING-SCHEMA` 支持范围收缩：旧 envelope、旧 prompt 运行及旧模型输出不再读取、恢复或转换。没有迁移命令、自动改写或删除；旧文件保持原样。用户选择新的空知识目录，从原始日志重新提炼。运行存储由 v2 显式升到 v3，旧运行不兼容，包括使用 v3 prompt 的旧 v2 运行；知识历史仍为 v2。提示词字节和接纳语义未改变，历史质量证据不重算。

每次写入通过工作区的 `.knowledge-write.lock` 串行化。只有本机 PID 经 SIG0 返回 ESRCH 证明确已退出的锁可以恢复；不凭年龄或运行状态抢占。恢复者按原 owner 身份串行，避免删除后来接管的活跃锁；中断的恢复锁也遵守同一规则。

## 7. 质量与完成证据

案例在模型运行前冻结重要提及、允许的对应、必须分开的对象、未消解指代及知识中的主体／对象。来源为合成案例，不能声称覆盖真实用户总体。编写者与复核依据的限制在报告中明确。

分别报告重要提及遗漏、误识别、错误对应／误合并、擅自消解，以及知识角色错误。精确原文匹配证明定位；引用闭合证明结构；两者都不单独证明语义正确。必要对照保留逐例输出、输入／prompt 摘要、实际用量及失败。

完成须同时有：独立实体结果、可操作的核对纠正、知识共同身份与修订绑定、空结果及部分失败／中断恢复验证、当前格式及不支持版本的拒绝验证、语义质量报告、真实入口验收、双语文档、自主 CR 及交付门禁。跨日志关联和跨 Agent 复用收益不由本轮推断。

已完成的[质量报告与原始证据](../explanation/entity-extraction-quality.md)分别呈现结构结果、精确位置、Agent 语义复核及未知费用。报告支持冻结合成案例中的独立实体覆盖，不证明知识对象错误减少或经独立复核的真实日志质量。
