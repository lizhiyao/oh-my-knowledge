# 实体知识库

## 目标与范围

本设计承接实体提取的 beta 能力，在用户明确选择的一个知识工作区内，围绕实体组织跨会话知识。首批通过知识列表、实体知识页、来源与组织历史支持阅读、维护和载体生成；图谱是后续可选视图。

实体是组织入口，知识是有场景、条件、时间和依据的事实、案例或方法。一条知识可以关联多个实体；识别出实体不要求生成知识，保留知识不代表真实性已验证。

## 身份与确认

窗口内的 `analysisId`、`entityId` 和实体修订继续由实体分析拥有。知识库对象使用独立 `objectId`，表示用户维护的持续组织入口，不替换来源身份，也不改变知识主张。

每条组织关联保存 `analysisId`、`entityId`、精确 `entityRevisionId`、至少一处属于该实体的 `mentionIds`，以及关联理由。创建或改变关联须明确确认同一对象、核对原文；服务端在工作区写锁内检查来源可读、提及匹配、当前实体修订、对象层次相同及身份无未解决歧义。名称一致不建立关联。语义是否同一仍由确认者负责，程序校验不是事实判断。

一个窗口实体最多属于一个当前知识库对象；不同对象的关联写入共享工作区锁。组件、实例、版本等不能作为同一对象关联；它们仍可通过知识中的关系互相找到。苹果水果与苹果公司、跨项目同名对象必须分别确认。知识库对象层次在历史中固定，需要改变含义时新建对象并显式解除旧关联。

## 存储与维护

新增 `library/<object-id>.json`，格式为 `knowledge-library-object-history`、`schemaVersion: 1`。每个对象保存不可变修订、父修订、作者、时间、理由、generation、写头和幂等收据。修订记录对象名称、用户维护简介、层次与完整关联集合；解除最后一条关联后仍保留空对象及历史。

写入需携带预期 generation／写头，拒绝过期草稿；原子写入前检查容量和成员占用。不可读的组织文件使查询与写入失败，不将其跳过后宣称对象未被占用。复用现有工作区锁及本机死进程锁恢复，不另建后台写入或自动重试。

组织层保持当前 `items/`、`entities/`、`sources/`、`tags/`、`artifacts/` 格式与内容，无需迁移。独立的 [extraction-run v5 升级](../entities/entity-extraction.md)使用 `extraction-runs/`，保留原 `runs/` 文件但不读取或迁移；当前实体与知识历史仍为 v2，可继续在同一工作区组织。组织层不保存知识正文副本，不修改提取提示词、Schema、程序接纳或历史分数，也不为旧结构增加兼容 reader。

## 知识投影与修订

对象知识页从关联的窗口实体找到知识当前修订，按知识身份去重，保留该修订的正文、来源、标签、条件、例外、未知、证据分类和维护决定。知识实际绑定的实体修订必须与确认的组织关联一致；不一致的知识另列为关联待核对，不能进入本对象已保留知识或初始载体选择。

实体新修订不会自动升级组织关联或知识。用户核对实体、明确应用到知识后，再以来源依据更新组织关联。旧知识、旧组织关联及其依据仍在历史中。已解除关联的知识不再属于当前对象，但知识自身不会被删除。

组织历史展示所选关联修订与知识当前状态，并明确它不是过去时点的完整知识快照。知识历史由知识详情查看。重复、否定、不同条件及冲突主张并列呈现；时间顺序不裁决真假，集合知识也不分配给成员。

来源缺失后可阅读已保存内容并解除关联；增加或改变来源关联需先恢复可核对来源。知识集合不可读时数量显示未知，不显示为零。所有派生视图保留范围提示。

## Studio 动线

知识分区提供“知识库”入口。用户搜索并选择对象，默认阅读已保留知识；待核对、已舍弃及组织关联待核对分别可达。对象页提供用户维护简介、知识全文与条件、精确来源入口、相关对象、来源实体及组织历史。

从实体详情可将其加入知识库，或打开当前所属对象。组织编辑中选取另一窗口的实体，核对描述、限定、提及和原文后填写理由并确认。解除、更新或修改简介生成组织新修订，不修改实体或知识正文。

从对象页选取适合任务的已保留知识，进入现有 skill／prompt 生成与保存流程；初始选择只包含精确匹配的保留项。载体生成不额外调用模型，保存、实际使用及效果验证分别记录。知识修订或保留决定变化后的预览冲突沿用载体现有保护。

列表和详情约束在应用视口内，通过内部滚动、分页和窄屏切换保持操作可达。错误、空对象、无已保留知识、来源缺失和旧修订均有明确提示；实体核对不成为每次提炼的前置步骤。

## 验收与限制

先复用既有脱敏真实 SDK 维护记录的两个不重叠窗口：早期 protected 覆写审查及后期公开接口改造。围绕同项目 SDK core 核对身份与知识；后期旧输出把 core 记作普通对象，若来源支持，将其在本地副本显式纠正为组件并应用到知识新修订。该维护不回填为自动提取结果，不改写原输出或历史分数。

验收覆盖跨窗口关联与解除、同名分离、层次／歧义拒绝、多实体入口、精确修订、保存／重开、原文和历史、来源缺失、冲突、空结果及载体保存。使用现有输出不产生模型调用；正常、较矮及窄屏 Studio 动线另行验收。

本阶段验证知识库功能可用性，不证明总体实体准确率、知识真实性、跨 Agent 自动归并或任务收益。记录操作成本与限制，将真实后续使用证据交给知识价值研究；不以数量或界面完成代替收益。
