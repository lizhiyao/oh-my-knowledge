# 知识维护、自动提炼与载体契约

本页集中维护已实现的标签、自动提炼授权、载体保存／重建、变化提醒和关联评测行为。用户先读[知识维护动线](../../guides/knowledge/extract-knowledge.md)，本文按需要查核字段、存储与失败边界；知识正文和组织关联分别以领域模型及知识库规范为准。

## 对话自动提炼与项目待办

在对话页头选择**开启自动提炼**。先核对最近 3 个已结束轮次的初始消息，明确候选目录、执行器、模型和最多调用次数（1～20 次），勾选发送授权后选择**批准并开启**。美元费用未知，次数上限不是美元预算。打开预览不会调用模型。

授权仅限这一条对话，有效期 24 小时，且只在当前 Studio 服务运行时生效。之后每次最多处理 3 个新增已结束轮次，并带上前 2 轮上下文；记录稳定 30 秒后开始。进行中或状态未知的轮次等待结束；不读取整条历史来判断所有纠正。同一来源窗口不会重复发送，不能据此保证语义重复已经消除。失败或中断停止，不自动重新调用；**停止自动提炼**会取消本服务的进行中调用。停止时已产生的输出仍可能被保存。重启后需要重新开启；失败窗口如需重新生成，使用手动提炼并再次确认。

页头的**知识待办**显示待核对数量，点开即可在原页面保留、舍弃或修订候选，按需检查实体，再从已保留内容生成并保存载体。每轮的**提炼这轮**和页头的**提炼整条对话**继续支持手动选择消息，结果也可就地核对。项目列表提供相同的**知识待办**入口，汇集当前已索引项目对话的候选与处理状态；这是来源分组，不是知识归属、相似或冲突的自动判断。当前目录无法读取或尚无候选时直接显示相应状态。

调度权限与调用预留另存为当前知识目录下 `auto-extraction/<thread-hash>.json`，使用 `schemaVersion: 1` 和 `automationKind: conversation-knowledge-extraction`。调用前持久化次数和窗口摘要；预留计入额度，中断后即使未实际发送也不返还、不重新发送。每个 Studio 最多登记 32 个对话范围，串行调用；每条对话最多记录 2,000 个已结束轮次及 1,000 个已尝试窗口，超限停止。另以不可变的 `permission-<id>.json` 和 `attempt-<run-id>.json` 保留历次授权及每次调用与来源窗口的关联，不因重新开启而覆盖；目录最多 3,000 个文件。现有来源、知识历史、实体历史与运行格式不变，原始依据不覆盖。明确注入的完整 AGENTS.md 规则仅在阅读视图折叠，原文可展开，来源快照和发送预览仍保留原始消息。


一次工作区写锁内的核对共享 invocation 回执清单，每份需要核对的回执在该过程中至多读取、解析一次；后续事务重新读取，不永久缓存回执核对结果。已发布 cooldown fact 的热缓存只记录成功完成的耐久确认，最多保留 3,000 项，并在服务关闭时清空。每次观察仍完整读取 fact 字节、校验 Schema 和回执绑定身份，重新计算字节摘要并核对实际文件身份；不能仅凭相同大小或时间戳跳过。缓存未命中或失效时，同步 fact 文件及其两级父目录，再复读确认字节和文件身份未变，成功后才缓存；失败清除该项，后续核对重新确认。缺少 fact 的冷恢复先校验 run manifest，再完整读取、校验所指 attempt 的 outcome，不先解析该 run 的全部 native 归档；真实执行、恢复及写入仍保留原有完整归档校验。调用额度不退款、已知冷却和持久化之后的到期／取消检查保持不变。

Studio 每 5 秒继续读取实际状态，即使自动提炼尚未开启或已经停止；每个自动提炼组件在当前对话范围内最多一个轮询请求在途。成功响应始终为带完整 JSON 的 HTTP 200 和 `Cache-Control: no-store`，不使用条件请求或 304。可选弱 `ETag` 只作界面失效提示，由选中目录／对话、当前自动提炼状态及已发布的知识、run、标签和实体 JSON 头文件元数据派生，不是内容完整性摘要、接纳证明或持久身份。有效 tag 未变时省略重复的待办重投影；初始化、tag 改变或缺失时刷新。冷却、运行完成、停止及人工保留／舍弃／修订等头文件变化仍可在后续 5 秒轮询中触发刷新，本页人工维护的既有变更通知仍可立即刷新。旧对话或停止前的迟到状态响应不能覆盖新状态。

待办队列先按选中对话／项目过滤 run manifests，再只读取这些 run 已提交的 knowledgeId 所对应的知识历史及标签，不先解析全部知识历史。目录枚举、run manifests、状态／回执核对、fact 完整字节读取和刷新 tag 的元数据扫描仍会发生；这不承诺零 I/O。上述优化只减少重复耐久确认与无变化的待办重投影，不减少模型调用次数，不缓存模型／请求身份核验结果，也不减少其重哈希或调整既有准入时机；持久 Schema、历史字节、授权与统计口径保持不变。

## 组织与检索知识


在候选详情的“主题标签”中编辑并明确保存标签。使用中文、字母、数字、下划线、连字符或 `/` 表示层级，不含空格，也不能只有数字；单条知识最多 32 个标签，每个最多 80 字符。重复标签不区分大小写。标签由用户维护，不额外调用模型，也不表示内容已验证；编辑标签不改变知识陈述、来源、修订或保留决定。

列表搜索支持标题与标签。输入 `tag:排障` 可匹配“排障”及“排障/证据判断”等子标签，并可结合处理状态筛选。标签用于组织主题，知识类型、适用条件和证据分类仍来自对应知识修订，不用标签替代这些字段。

标签历史单独保存到知识目录的 `tags/<identity-digest>.json`，使用 `omk-knowledge-tags/v1`，绑定知识身份，记录标签、修改时间与操作者。标签保存不改动知识、来源或运行记录。未设置标签时为空；并发修改拒绝旧 generation，读取后核对再保存。标签属于知识的组织信息，知识修订后仍保留，需核对它们是否仍适用。


## 生成并保存知识载体


在已保留候选或本批核对完成页点击“生成知识载体”，或在“知识载体”中点击“从已保留知识生成”。选择 skill 或 prompt、填写名称，核对所选的已保留知识，再点击“生成并核对内容”。初始选择只包含当前候选或当前批次的保留项；可明确增加其它保留项，单次最多 100 条。生成按已有内容组织文本，保留条件、例外、未知项、陈述与依据分类、原文摘录及来源版本，不额外调用模型。

生成时同时带出元信息快照：标题、摘要、主题标签、知识类型、场景、证据分类及精确知识／来源版本。摘要取自知识标题，场景取自陈述上下文，证据分类可包含多种类型；`verification_status: not_assessed` 表示本次生成不提供真实性或任务效果验证。prompt 使用顶部 YAML properties，`tags` 为列表，可供 [Obsidian](https://obsidian.md/help/properties) 等工具读取；skill 保持必需的 `name`／`description`，额外属性写入规范允许的 `metadata` 字符串映射，列表编码为 JSON 字符串。

元信息使用 `omk-knowledge-metadata/v1`，描述该版载体所纳入知识的快照，不是可回写知识库的管理入口。更新 OMK 生成的载体会重算这些属性；首次导入本地 prompt 时保留已有自定义字段和标签。标签在预览后变化也会拒绝旧预览。旧载体不会被后台改写，`manifest.json` 继续承担载体及知识修订关联的权威记录。

核对并编辑新内容后点击“保存载体”，会直接保存到当前知识目录的 `artifacts/<artifact-id>/vN/content/<directory-name>/SKILL.md` 或 `artifacts/<artifact-id>/vN/content/<directory-name>.md`，随后进入载体详情，显示实际载体路径、内容、来源知识和历史版本。显示名称支持中文；新载体的文件名称自动生成独立标识，skill 头部的 name 与目录名一致，保存时核对有效头部，遵循 [Agent Skills 格式](https://agentskills.io/specification)。无需复制粘贴到其它位置。来源链接定位到实际使用的知识修订。保存不代表内容已证实或改动已有效，使用前仍需检查适用范围并进行受控评测。

更新已有载体时，可选择已保存载体，或明确指定一个本地文件。已保存载体按本次明确选择的当前已保留修订重建知识区，未选知识从新版本移除，正文、属性和清单只引用本次选择；知识区外的手工内容及依赖资产保留。新知识区使用 `omk:knowledge:v1` 边界标记；无标记旧版本仅在知识后缀与清单的精确修订完全匹配时迁移，无法安全识别则拒绝重建，需另建载体并核对手工内容。可切换原内容核对，保存为新版本，旧版本完整保留。基于本地 `SKILL.md` 生成时保留原内容并复制同目录的可分发资产，沿用既有过滤与内容摘要规则；原文件不会被覆盖。知识保存目录不能位于被复制的本地 skill 内部，需要另选目录。回看旧版本时，需要选择最新版本才能继续生成更新。

载体列表的“知识复核”和详情的“变化核对”按读取时状态检查已有引用：新修订、当前未保留，以及知识或来源不可用都会提示复核；文件被外部修改另行标示。详情展示检查时间、变化范围，以及载体引用的精确旧修订与当前修订正文。点击“重新核对知识变化”刷新；读取失败不代表没有变化。检查不覆盖未引用的新知识，不判断内容真伪或语义过时，也不会自动更新载体或维护决定。生成新版本时，“本次引用变化”列出新增、替换、移除和沿用的修订，结合原内容核对后保存；最新版本的引用变化提醒随新读取结果更新，旧版本仍按其历史引用复核。

每版 `manifest.json` 使用 `omk-carrier-v1`，记录载体身份、版本、保存时间、内容摘要、文件目录名、基线及精确知识修订关联。该目录是新增的载体保存契约，不改写候选、来源快照或既有评测数据；知识复核是读取时的派生结果，不写入历史清单。知识当前修订、保留决定或基线载体在预览后发生变化时，保存会拒绝旧预览，需要重新生成；外部修改的载体会标示内容变化。版本通过临时目录整体发布，失败或取消不会替换旧版。同机写入进程中断后，超过 30 秒的失效锁由下次保存恢复，并清理未发布的临时版本；不会抢占其它主机的锁。保存结果未能读取时先“核对已保存版本”，避免重复写入。


## 从载体验证改动


在载体详情点击“验证这个版本”。更新已有载体时自动带入原版本；新建载体可选择其它已保存版本或明确指定本地 skill 目录／SKILL.md、prompt 文件作为基线。两个版本必须形式一致且内容不同。选择本地用例文件或目录、执行器与固定模型，可配置模型评委，再点击“预览评测计划”。当前入口支持 1–100 个本地用例，不支持需要远程内容解析的用例。

预览展示两个版本内容、相同用例与评分依据、执行模型、实际评分模型及计划任务数量；不会调用模型。核对后点击“确认并开始评测”才开始运行，包括必要预检。费用无法提前准确估算，预检和模型评分可能增加调用；无自动重试。预览有效期为 15 分钟，载体、用例或运行计划变化时拒绝旧预览，需要重新核对。

“评测记录”关联精确载体修订和知识来源，保留结束、失败、取消及中断状态，可取消运行、打开原有 Core 结果与证据，再返回实际待测版本。取消不能撤销已经发生的调用或费用。启动响应未读到时先“核对运行状态”，避免重复调用；服务关闭取消其持有的运行，同机进程退出后的运行记录显示中断，不会自动恢复模型调用。已有 Studio 评测记录仍可访问。

这一路径以所选知识目录作为操作目录，Core 产物使用既有 `.omk/eval` 契约；新增 `.omk/state/jobs/carrier-measurements/<measurement-id>.json` 使用 `omk-carrier-measurement-v1` 保存预览与运行关联，不修改载体 `manifest.json` 或既有测量 Schema。记录可能包含所选用例与载体的私有内容，按本地数据管理。运行结束、载体保存或知识保留都不等于效果已验证；结论与证据范围以报告为准，生成用例需要复核，不能自动作为独立发布验证证据。
