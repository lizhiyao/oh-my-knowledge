# 知识维护、自动提炼与载体契约

本页集中维护已实现的标签、显式提炼及旧自动调度边界、载体保存／重建、变化提醒和关联评测行为。用户先读[知识维护动线](../../guides/knowledge/extract-knowledge.md)，本文按需要查核字段、存储与失败边界；知识正文和组织关联分别以领域模型及知识库规范为准。

## 对话自动提炼与项目待办

当前 `knowledge-body-first/v4` 仅允许逐阶段执行：来源盘点 → 正文 → 来源覆盖 → 实际操作者决定 → 关联。每个模型阶段独立预览完整请求并确认摘要；来源覆盖意见不等于内容批准，也不自动保留正文或更新载体。

旧对话自动调度已退役。状态返回 `unsupported`／`explicit_stages_required`；预览、开启或后台 tick 都不会创建模型、配置执行器、派发或写许可。停止／关闭不修改旧权限、调用预约、unknown claim 或原件；迁移只归档它们。独立副本迁移后也不能重新授予自动许可，须使用显式逐阶段入口。

对话／项目**知识待办**继续按选定来源对话组织正文 ID，不赋予共享实体身份。支持保留／舍弃／正文修订及独立关联审查；显式提炼完成或同工作区维护事件刷新待办，不依赖退役自动状态轮询。存储与恢复见[工作区契约](../shared/storage-layout-spec.md#explicit-knowledge-workspace)。

## 组织与检索知识


在候选详情的“主题标签”中编辑并明确保存标签。使用中文、字母、数字、下划线、连字符或 `/` 表示层级，不含空格，也不能只有数字；单条知识最多 32 个标签，每个最多 80 字符。重复标签不区分大小写。标签由用户维护，不额外调用模型，也不表示内容已验证；编辑标签不改变知识陈述、来源、修订或保留决定。

列表搜索支持标题与标签。输入 `tag:排障` 可匹配“排障”及“排障/证据判断”等子标签，并可结合处理状态筛选。标签用于组织主题，知识类型、适用条件和证据分类仍来自对应知识修订，不用标签替代这些字段。

标签历史单独保存到知识目录的 `tags/<identity-digest>.json`，使用 `omk-knowledge-tags/v1`，绑定知识身份，记录标签、修改时间与操作者。标签保存不改动知识、来源或运行记录。未设置标签时为空；并发修改拒绝旧 generation，读取后核对再保存。标签属于知识的组织信息，知识修订后仍保留，需核对它们是否仍适用。


## 生成并保存知识载体


在已保留候选或本批核对完成页点击“生成知识载体”，或在“知识载体”中点击“从已保留知识生成”。选择 skill 或 prompt、填写名称，核对所选的已保留知识，再点击“生成并核对内容”。初始选择只包含当前候选或当前批次的保留项；可明确增加其它保留项，单次最多 100 条。生成纳入完整正文段，保留条件、归因、否定、例外、未知、inline 依据类型、原文及来源版本，不额外调用模型；派生关联变化不改载体正文。

生成时同时带出元信息快照：摘要、主题标签、可选知识类型、依据类型、精确知识修订／body digest 与来源版本。摘要取自知识标题，必要场景留在完整正文，不从 typed context 推导；多种依据类型可共存。`verification_status: not_assessed` 表示本次生成不提供真实性或任务效果验证。prompt 使用顶部 YAML properties，`tags` 为列表，可供 [Obsidian](https://obsidian.md/help/properties) 等工具读取；skill 保持必需的 `name`／`description`，额外属性写入规范允许的 `metadata` 字符串映射，列表编码为 JSON 字符串。

元信息使用 `omk-knowledge-metadata/v2`，描述该版载体所纳入知识的快照，不是可回写知识库的管理入口。更新 OMK 生成的载体会重算这些属性；首次导入本地 prompt 时保留已有自定义字段和标签。标签在预览后变化也会拒绝旧预览。旧载体不会被后台改写，`manifest.json` 继续承担载体及知识修订关联的权威记录。

核对并编辑新内容后点击“保存载体”，会直接保存到当前知识目录的 `artifacts/<artifact-id>/vN/content/<directory-name>/SKILL.md` 或 `artifacts/<artifact-id>/vN/content/<directory-name>.md`，随后进入载体详情，显示实际载体路径、内容、来源知识和历史版本。显示名称支持中文；新载体的文件名称自动生成独立标识，skill 头部的 name 与目录名一致，保存时核对有效头部，遵循 [Agent Skills 格式](https://agentskills.io/specification)。无需复制粘贴到其它位置。来源链接定位到实际使用的知识修订。保存不代表内容已证实或改动已有效，使用前仍需检查适用范围并进行受控评测。

更新已有载体时，可选择已保存载体，或明确指定一个本地文件。已保存载体按本次明确选择的当前已保留修订重建知识区，未选知识从新版本移除，正文、属性和清单只引用本次选择；知识区外的手工内容及依赖资产保留。新知识区使用 `omk:knowledge:v1` 边界标记；无标记旧版本仅在知识后缀与清单的精确修订完全匹配时迁移，无法安全识别则拒绝重建，需另建载体并核对手工内容。可切换原内容核对，保存为新版本，旧版本完整保留。基于本地 `SKILL.md` 生成时保留原内容并复制同目录的可分发资产，沿用既有过滤与内容摘要规则；原文件不会被覆盖。知识保存目录不能位于被复制的本地 skill 内部，需要另选目录。回看旧版本时，需要选择最新版本才能继续生成更新。

载体列表的“知识复核”和详情的“变化核对”按读取时状态检查已有引用：新修订、当前未保留，以及知识或来源不可用都会提示复核；文件被外部修改另行标示。详情展示检查时间、变化范围，以及载体引用的精确旧修订与当前修订正文。点击“重新核对知识变化”刷新；读取失败不代表没有变化。检查不覆盖未引用的新知识，不判断内容真伪或语义过时，也不会自动更新载体或维护决定。生成新版本时，“本次引用变化”列出新增、替换、移除和沿用的修订，结合原内容核对后保存；最新版本的引用变化提醒随新读取结果更新，旧版本仍按其历史引用复核。

每版 `manifest.json` 使用 `omk-carrier-v1`，记录载体身份、版本、保存时间、内容摘要、文件目录名、基线及精确知识修订关联。该目录是新增的载体保存契约，不改写候选、来源快照或既有评测数据；知识复核是读取时的派生结果，不写入历史清单。知识当前修订、保留决定或基线载体在预览后发生变化时，保存会拒绝旧预览，需要重新生成；外部修改的载体会标示内容变化。版本通过临时目录整体发布，失败或取消不会替换旧版。同机写入进程中断后，超过 30 秒的失效锁由下次保存恢复，并清理未发布的临时版本；不会抢占其它主机的锁。保存结果未能读取时先“核对已保存版本”，避免重复写入。


## 从载体验证改动


在载体详情点击“验证这个版本”。更新已有载体时自动带入原版本；新建载体可选择其它已保存版本或明确指定本地 skill 目录／SKILL.md、prompt 文件作为基线。两个版本必须形式一致且内容不同。选择本地用例文件或目录、执行器与固定模型，可配置模型评委，再点击“预览评测计划”。当前入口支持 1–100 个本地用例，不支持需要远程内容解析的用例。

预览展示两个版本内容、相同用例与评分依据、执行模型、实际评分模型及计划任务数量；不会调用模型。核对后点击“确认并开始评测”才开始运行，包括必要预检。费用无法提前准确估算，预检和模型评分可能增加调用；无自动重试。预览有效期为 15 分钟，载体、用例或运行计划变化时拒绝旧预览，需要重新核对。

“评测记录”关联精确载体修订和知识来源，受支持的 v2 记录保留结束、失败、取消及中断状态，可取消运行、打开 Core 结果与证据，再返回实际待测版本。取消不能撤销已经发生的调用或费用。启动响应未读到时先“核对运行状态”，避免重复调用；服务关闭取消其持有的运行，同机进程退出后的运行记录显示中断，不会自动恢复模型调用。已有 Core 结果与证据仍以各自支持的格式范围为准。

这一路径以所选知识目录作为操作目录，Core 产物使用既有 `.omk/eval` 契约；`.omk/state/jobs/carrier-measurements/<measurement-id>.json` 使用 `omk-carrier-measurement-v2` 保存预览与运行关联，不修改载体 `manifest.json` 或 Core 测量 Schema。当前读取器不读取或恢复旧 v1 侧车；原件保留为历史，需针对明确选定的当前来源和载体重新预览新计划。记录可能包含所选用例与载体的私有内容，按本地数据管理。运行结束、载体保存或知识保留都不等于效果已验证；结论与证据范围以报告为准，生成用例需要复核，不能自动作为独立发布验证证据。
