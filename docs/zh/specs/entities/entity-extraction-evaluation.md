# 实体提取质量验收

当前契约：指南 `omk-entity-annotation/v11`，语料 `omk-entity-quality/v13`，检查器 `omk-entity-critical-checks/v5`。生产 prompt-json `knowledge-extraction-v29`、strict `knowledge-extraction-v30`、响应 Schema v4、run v5 与 quality 投影 v4 分别保留身份，均不继承历史 v14／v18 的模型质量或 Gold 结论；独立身份的 bounded 重试／预算政策同样需要自己的固定测量。quality v4 保留 v3 按完整政策与初始调用上限分组，v2→v3 的变化仍属于 **BREAKING-COMPARABILITY**；每个 run 最终选定的出生接纳只计一次。独立版本的人工封存将 current 记录作为执行状态未知保留在分母中，不支持 schema 及 legacy 处置分别可见；它不补造接纳或语义通过。

独立登记的[历史 v14 真实窗口基线](entity-extraction-real-v14-baseline.md)维护其原始证据及限制，不是当前 strict 双臂实验或独立质量验收。人工确认的跨窗口组织已通过[实体关联日志](entity-links.md)与知识库实现，不合并来源身份，其提案另行遵循[关联评测协议](entity-link-evaluation.md)。组织决定及历史提取证据均不证明自动跨 Agent 身份或复用收益。

当前 `test/fixtures/entity-extraction-review-v13.json` 原样保留 v12 的 60 个公开合成窗口、199 处关键提及，新增四个工作记录／概念边界的开发窗口；总计 64 个窗口、212 处关键提及，其中 62 个开发窗口与 2 个预留验证窗口。完整名称备选、身份、知识角色及逐例理由以冻结语料为准；它不是隐藏盲测集，也不代表真实日志分布，不含真实消息正文。已查看输出的窗口只作开发回归，不能用于宣称盲测收益；新的验证窗口须按项目／会话隔离并在输出前确定，不用于提示词调参。真实日志另行最小化、授权、分组和复核。

## 2. 标注单位与允许表达

先冻结来源消息、角色、缺失记录及窗口限制，再逐项标注：

| 标注 | 规则 |
|---|---|
| 关键提及 | 标注对检索、身份或知识理解必要的名称和指代；不是标全体名词。保留消息序号、原文和从零开始的出现序号；重叠匹配计数，位置为 UTF-16 半开区间。 |
| 允许边界 | `alternatives` 只能列出输出前已确认的等价边界，例如完整代码标识含或不含反引号、指向同一对象的短名和完整限定描述。不能用任意包含该名称的大段引文充当命中；边界扩大仅列为待复核候选。 |
| 身份组 | 同一个 `entityKey` 的提及必须归并，不同身份组必须分开。模型 ID 和标签不作答案；通过原文位置对齐后比较提及对。 |
| 层次及关联 | 标明允许的 `referentKinds`、身份状态、明确候选、组件和集合成员／完整性。只有指南允许的表达才能作为备选；来源不明时保留未知。 |
| 知识角色 | 先标来源锚点、主体、对象和解释。自然语言关系允许同义表达；语义、方向、否定、条件、时间和纠正由人工按全文判断，不能用关键词缺失判错。 角色须预先标 `coverage: required` 或 `if_selected`。 |

集合指代是一个集合提及，不能复制为多个成员的同跨度提及。实例／版本与组件分开；仅改变环境条件不强制拆身份。工具和日志、计划和执行、删除后新建与改名分别处理。同名或相同路径不足以归并。来源截断不自动要求空知识；可记录未消解主体的来源主张与待调查状态，不补充缺失身份或推广结论。确实存在两种合理身份方案时，先裁决，或在输出前显式表达允许方案；当前契约不支持多个相互冲突的身份分区，争议未解决的案例不能冻结。

提及边界按[身份规则 §2.3](./entity-identity.md)判断对象含义，不以最短字符串为目标。“当前 main 的被测代码”与“enabled 字段”仍指同一对象，可在新测量的输出前列为备选；“main 上的改造”谈改造这一属性，代码状态提及应选择其中的 `main`。不机械裁剪“字段”“的”“上的”等词，也不接受任意包含短名的句子。程序继续精确匹配预先声明的备选，不自动裁剪或用正则替代语义判断。收窄重复短名时重新计算 occurrence；第二处 `main` 的序号为 1，不能沿用只出现一次的长短语序号。

类型依据与身份消解分别判断：名称、调用、故障或“节点”称呼不能单独证明组件／部署实例。身份已知但类型未知用 proposed object，保留类型依据不足；来源明确的模块职责或部署实例不能降为 object。完整限定描述与短名可以预先列为等价边界，但不能看新输出后放宽。共同指代与其属性分别识别：their／它们 指集合，属性短语不能只归给一个成员。关系与 polarity 必须一起读，不能重复否定；“未失败”不等于“成功”，“未禁止”不等于“要求”。这些判断保留在逐例语义标准中，不由关键词规则代替。

开放识别须逐例核对普通实物、抽象概念与专有对象的覆盖，以及 description 是否忠实说明语境中的含义。语义类别不等于 referentKind；概念和具体对象可以都用 object，不能因层次相同而合并。保险产品名字含“计划”不证明 plan。记录关键提及之外的遗漏、误提取和未经来源支持的类别／含义；未穷尽标注不计算总体 precision／F1。没有知识候选仍须核对实体覆盖；只有空知识结果不能证明知识关联可靠。

沿用的逐项语义核对另需确认：核心概念不被统计／适配对象替代，概念短跨度与复合对象完整跨度可以重叠但不能复制同一跨度；产品名含词不自动拆概念。助手选择回答不等于用户澄清，最初含糊提及保留 unresolved 及同层候选（层次不一致时空候选加理由），明确澄清后才重新判断先前提及。一条 statement 只有统一 modality／polarity 的命题，正负要求分开陈述、分别引用；不能靠 context 将单一 negative 限定到后半句，也不能将一个集体谓词机械拆成成员事实。这些标准由逐例复核执行，结构接纳不使用关键词推断或补写结果。

引用语境核对沿用既有身份与限定规则：教学示例、假设或反例中的对象与真实当前对象分别依据各自语境识别，不能因名称相同而合并，也不能把示例的版本、环境或结果搬入当前实体的 description／qualifiers。mention 及理由须支持它所绑定的那个对象。来源明确跨引述仍指同一对象时须归并；引号或“示例”标签不能自动触发拆分。对应关系没有确认时保留 unresolved 与有依据的候选，不凭助手续答自行澄清。精确提及和身份分组检查不证明限定有来源；该项仍经完整窗口逐项语义复核。

粒度核对同时检查遗漏与过度拆分：先判断来源是在描述事物的属性／行为，还是在独立定义、比较、指向或关联一个对象，再决定身份。普通属性可用关于所属对象的陈述表达，独立指标／操作概念不能因为属于统计／过程而被折叠。没有专名或知识候选不是排除依据；数值、单位、条件和未确认结果仍须保留在陈述中。关键提及命中不能证明这一边界正确；额外实体、实际知识文本和未生成的可选知识都须逐例记录，自审不称独立证据。不得根据输出事后修改身份方案。

模态否定须按来源含义复核，以下是允许的等义表达示例，不是关键词分类器：

| 来源说法 | 可用表达 | 不可推导 |
|---|---|---|
| 无需修改 SDK | descriptive／negative，“需要修改”；否定本场景的必要性。 | 禁止修改、未实际修改。 |
| 不应修改 SDK | normative／negative，“修改”。 | 没有修改必要性、已遵守要求。 |
| 未禁止修改 SDK | descriptive／negative，“修改受到禁止”；否定禁止状态。 | 明确授权、要求修改、已修改。 |
| 明确允许／禁止修改 SDK | permission／positive 或 negative，“修改”；保留授权主体和范围。 | 其它场景的权限、执行结果。 |

转述的要求仍保留 normative／permission，证据为 source_assertion，context 保存说话者、条件、时间与适用范围；描述性陈述也可以保留来源说法，并不自动成为直接观测。否定必要性／禁止状态时，relation 必须保留该被否定谓词，不能一律缩成行动。“不能修改”需结合语境区分能力不足和禁令。只在 context 写“无需”不能挽救正文已写成禁令的语义；确实无法表达时保留未知或不提炼。各语气和条件须独立引用，未生成可选知识记为 not_observed，不算语气通过。

分支／被测状态按[身份规则 §3.1](./entity-identity.md)核对：分支 object 与单独指向的代码状态 version 区分，缺 SHA 不等于身份未消解；允许层次备选须先冻结。采用分支主体仍须限定本次状态／来源时间；不同提交不合并，日期不自动拆分支，未知复现标识及未发布状态保留。

配置知识按[身份规则 §2.2](./entity-identity.md)核对：选中相关知识时，保留影响判断／复用的精确值、类型、所属对象、范围、条件、来源理由及未知。已有所属对象可以为主体，但须明确字段和值；字段端点差异只是待核对线索。description、qualifiers 或引文可查不代表陈述完整。角色 `coverage: required` 预先要求事实覆盖；`if_selected` 仅在选择相关知识时检查信息保留。已有知识缺关键值是信息丢失，可选知识未生成是 not_observed，必需事实缺失是知识覆盖缺口，均与实体遗漏分开。`none` 不可含 required 角色。

工作记录复核遵守[身份规则 §2.4](./entity-identity.md)：来源独立讨论 Issue／PR 概念时保留，具体编号记录不单独建实体，也不剥掉标识补造概念。有用的记录编号、链接、状态和主张者仍保留在来源或案例 context。即使额外对象有原文依据，也须遵守此范围；记录实体属于输出范围错误，不自动等同于补造来源事实。不将这条边界推广到文件、部署实例、版本或所有具体对象。新输出前冻结这些判断；输出后显式纠正实体目录及知识时保留原修订，不提高原运行分数。

### 2.1 完整名称逐例审核流程

1. 对每个既有关键提及读取原文、身份组和所有边界，核对同一次出现，不把别处同名指代改作备选。
2. 向类型词、冠词／指示词、所属对象、位置和时间限定扩展；只纳入仍以同一对象为中心的连续名词描述。“已发布 r2”、“Its test instance `sieve/dev01`”和“昨天的更新活动 U1”都可构成限定名称，后接通过／失败／赋值等谓词必须截止。
3. 核对短语实际指向：项目 Pavo 的 a.md 指文件，客户端 L 的 errorStatus 指字段，可与所有者短提及重叠；不能将这些整段绑定到项目或客户端。复数成员列表不作为单体的名称，Session 计数不作为 Session 的别名。
4. 为每个增加的 quote 独立计算 occurrence 与 UTF-16 区间，保留旧备选、逐例增加理由和排除示例。程序仍精确匹配，不用任意包含名称的跨度或词尾正则替代审核。

审核覆盖全部既有关键提及，不声称穷尽所有可能的同义或嵌套描述，也不新增全文所有名词。输出后发现的新缺口必须保留当次严格 miss 与停止事实，另建明确版本的修订；既有输出仅离线核验覆盖与拒绝边界，不作为新模型质量证据。

### 2.2 关键来源定向诊断 v1

`test/fixtures/entity-source-coverage-v1.json` 是独立的 `omk-entity-source-coverage/v1` 合成开发案例：三条消息、两个对象、两处身份提及和五项关键知识依据（目的、当前限制、适用条件及例外、迟到约束、后续纠正及未验证限制）。它不并入主语料，不改变关键提及分母。

## 4. 独立复核、争议与冻结

1. 实现者／作者自行逐例检查语义、来源闭合、位置、分组及契约，保存 `omk-entity-author-review/v1` 记录及理由；`authorReview: completed`、`exploratoryReady: true` 表示可继续工程与探索性验收，不要求用户承担逐例复核。自审不计入独立人工证据，`goldReady` 仍为 false。缺少独立复核是报告的覆盖限制，不阻塞这些工作；独立质量完成门槛保持不变。
2. 与作者独立的人逐例检查指南、允许边界、身份组、角色及语义标准；在 `review-template.json` 填写每例 `approved` 或 `changes_requested`、理由、复核人、时间和独立性声明。独立模型评委不等同于独立人工复核。
3. 争议在看到输出之前裁决，记录问题、结论和独立裁决人。未解决时使用 `changes_requested`。需改语料／指南／检查器时升级相应版本并重新生成复核包，不能靠修改复核记录批准旧摘要。
4. 作者与独立复核记录均必须覆盖全部案例，绑定测量身份，并早于输出捕获。任一已提供记录要求修改时，两种 ready 状态均为 false，不能用自审覆盖独立异议。检查器拒绝作者自称独立、缺项、错误摘要和事后批准。它只能验证声明与记录闭合，不能验证复核人身份真实或保证其判断正确；`attested_independent_human` 表示有声明，不是效果结论。
5. 测量身份由语料、双语指南、已编译检查器及生产运行产物摘要、依赖清单／锁文件摘要、Node 版本、提示词原始 UTF-8 摘要和版本组成。运行产物摘要采用 `omk-entity-measurement-runtime/v2`：覆盖 `dist` 内所有普通文件的规范化相对路径与原始字节，仅排除无关的 Next.js 子树 `studio/web`。相关运行代码或资源变化仍会使身份失效；仅网页重建不会。该范围变化相对早期 bench 摘要属于 **BREAKING-COMPARABILITY**：重新准备复核包及匹配回执或 live plan，旧证据继续使用原冻结宿主，不迁移、不重评分。共享摘要模块计入检查器／采集器摘要，实体关联复核也包含该模块。复核包分别保留中英指南原始字节及便于阅读的合并稿。manifest 另记观测到的 `sourceRevision.commit` 和 `sourceRevision.dirty`，不进入测量身份；无法确定 Git 来源时两者均为 `null`。dirty 检出的 commit 不能复现未提交源码，也不能证明已有构建由哪份源码生成。运行时 promptHash 的规范化 JSON 摘要与这里的原始 UTF-8 摘要不同，不能混用。

## 5. 离线复核工具与证据

先更新编译产物，然后生成外置复核包：

```bash
yarn build:runtime
node dist-scripts/bench/entity-extraction-review.js \
  --corpus test/fixtures/entity-extraction-review-v13.json \
  --output /private/tmp/omk-entity-review-unique
```

输出目录必须绝对、在仓库外、父目录存在且目标未存在；即使通过软链指向仓库也拒绝。工具保存原始语料、双语指南、位置与答案展示 `review.html`、复核模板、模型输入及摘要、测量 manifest。未提供独立复核记录时 `goldReady: false`，即使作者自审完成也不变。模板默认需要修改且未签署，不能不经填写就批准。

可选 `--self-review /absolute/self-review.json` 校验作者自审记录（测量身份、作者、时间、逐例决定及理由），保存为 `self-review.json`；它无独立性声明，也不能经 `--review` 冒充人工证据。可选 `--review /absolute/review.json` 校验独立复核记录；可选 `--captures /absolute/captures.json` 只检查已有捕获。本命令**没有执行器入口，模型调用数始终为 0**，生成包或签署标注不授权数据发送或模型执行。

捕获格式 `omk-entity-captures/v1` 包含同一 `measurementId`、单一 split、1 或 2 次计划重复、开始时间、执行器和模型，以及 `caseId`、重复序号、冻结输入摘要和结果。结果为 `output`（原文与可选原始 usage）、`call_failure` 或 `cancelled`，可记录执行器实际报告的 `durationMs`、`costUSD`；未知值省略，不补零。检查未知／重复／超计划记录及输入摘要，完整保留原始捕获和接纳结果。未尝试记录逐项保存；没有完成检查的关键提及不进入命中分母，另列未检查数。只汇总已报告的用量、耗时和费用；任一已记录尝试未报告费用时总费用为 `unknown`，同时显示已报告部分，不能推测费用或将部分覆盖称为整轮成本。

结构拒绝不让捕获状态变成失败；调用／解析失败、取消或未完成计划使命令非零退出。程序成功退出仅说明离线检查完成。原始输出与逐项接纳、原始 usage 和全部失败均保留，报告继续显示语义复核待完成；仅有作者批准的捕获标为 `exploratory_semantic_review_pending`，不宣称独立验收通过。后续模型验收在具体授权范围内执行，并取得逐项独立输出复核。

### 5.1 显式覆盖复核研究任务

内部应用选项 `coverageReview.previousRunId` 通过 `knowledge-extraction-coverage-review-input/v1` 输入任务，把同一来源的首轮完整原生响应作为不可信候选交给模型，与原文对照后返回完整实体、提及和知识。首轮须为已结束的原文单次提取，模型、strict30 系统字节、wire、timeout 和输出配置相同；应用重新读取首轮归档并验证来源、输入与原件，不接受调用者提供的替代 raw。原输出及拒绝项保持原样，旧结果不成为来源引文。容量不足时在派发前失败，不截断候选。

复核是独立 run 的一次新调用，沿用原生归档、接纳和修订链；不自动拼接两份结果，也不在默认提取、重试或自动提取中启用。现有 study/v1 不支持两臂使用不同任务输入，不能用其 prompt／policy／replication 轴冒充这个流程比较。独立诊断须在派发前封存实际输入字节、前驱 run／attempt／outcome 摘要、宿主、顺序、最终端点选择与停止规则，再核对实际请求；旧输出仅作输入时，不计为新端到端结果。

对照为相同调用机会和执行配置的原文普通重提取，两臂预先选定各自末次完整结果。复核输入增加了候选目录，实际 token 和费用须分别报告，不能声称相同成本或纯提示词效果。所有实体、提及、知识、拒绝及源支持的信息保留仍须复核；局部修复不替代独立真人语义验收。

### 5.2 来源语义清单研究流程

另一内部候选先从原文生成语义清单，再根据原文及完整、未修改的清单生成完整实体、提及和知识。当前清单使用独立的 `knowledge-source-plan-system/v3`、`knowledge-source-plan-input/v2` 和 `knowledge-source-plan-wire/v2` 身份，输出名称为 `knowledge_source_plan_v2`，`schemaVersion: 2`；不提供 v1 reader 或别名。它表达被讨论的对象与有界组、分开的身份／层次依据、精确来源锚点、成员未知及带条件和限制的材料。检查器只验证结构、来源绑定、精确位置和局部引用闭合，始终明确保留 `semanticStatus: not_reviewed`。有效清单仍是不可信候选数据，不是新增来源证据或已接纳知识。

source-plan system v3 完整逐字接收 `ENTITY_REFERENT_KIND_POLICY`，与 A system v4、独立 v36 实体任务共享既有七种所指层次的含义和依据门槛。Schema 枚举本身不提供这些语义。私有规划词汇另允许在规划阶段层次依据不足时使用 `referentKind: unknown`，通过 `typeBasis` 与 `uncertainties` 保留该不足，与身份 `unresolved` 分轴，因此已知身份仍可为 `proposed`。共享政策中的一般 `object` 及有据兜底继续有效，但不要求把明确的规划层次未知替换为 `object`。

此次 source-plan system v2→v3 构成 **BREAKING-COMPARABILITY**。input、wire、响应 Schema 与检查器保持 v2；共享政策、A system v4、B system v4、v36／v37 及生产默认的字节与身份不变。新的 source-plan 请求须重新冻结任务／请求。依赖任务绑定完整 source-plan 回执，因此实际输入绑定也随之变化，须依据新的已认证前驱链物化并在派发前封存；旧执行许可或分数不能复用。历史原件、回执、冻结运行时及分数保持原样，使用各自匹配的冻结代码，不重新解释或重评分。规则传递不证明模型质量改善，也不增加 B→A 修订闭环。

对象通过 `planningRole` 与 `qualificationBasis` 区分 `entity_candidate`、`context_only`、`qualification_unknown`，与身份、类型、成员未知分轴。有独立讨论依据的概念、过程或门槛即使出现在条件中也可成为参与者；具体来源记录不能替代它们，词汇本身不决定资格。材料通过 `retentionIntent` 与 `reuseBasis` 区分 `reusable_candidate`、`context_only`、`undetermined`，并分开 `participantObjectIds` 与 `contextObjectIds`。完成报告中不同复用角色的内容须拆为材料单元，但不机械把每个条件变成新节点；一次诊断案例或数值语境仍可能具有复用价值。角色未知须有明确理由；这些角色仍是模型主张，不是宿主筛选、补齐或合并对象与知识的许可。最终阶段须回原文独立核对，不能凭上下文标签免除来源支持的可复用信息保留。

最终应用选项 `sourceSemanticPlan` 只接收回执 ID 与字节引用，可信研究组合根提供只读归档端口，普通宿主不安装该端口。应用验证完整回执／原生字节、同来源任务／请求／producer 身份、模型／timeout／输出配置及完整原生返回，再校验清单，之后才为最终调用预留。producer 检查重建第一阶段自己的 Schema，不与不同的最终提取 Schema 混比。归档缺失／损坏、清理失败、工具调用、拒绝和不完整的原生终止均不能续派；清单结构／锚点拒绝单独归为保留原始返回的质量失败。回执仅为本地来源记录，不是 provider 签名或真人复核。

最终请求使用 `knowledge-extraction-source-plan-input/v2`、不变的 strict30 及当前 v4 输出 wire，实际输入进入普通请求摘要；继续原生归档、接纳和修订链。清单锚点正确不能修复最终错引，仅出现在清单中的材料不算最终知识保留。该选项与覆盖复核互斥，仅允许单次调用 run，不经重试、CLI 或默认行为自动启用。没有公共存储迁移或通用任务平台，私有清单回执也不是失败的提取 run。

与“原文完整提取 → 现有覆盖复核”比较时，两臂从新的第一阶段开始，最终端点须事前确定。首次输出前冻结构造器、任务、来源／配置、阶段依赖、顺序、调用机会和停止规则；各第二阶段在首阶段归档后、派发前物化并封存实际输入，不能声称未知的未来输出字节已事前冻结。中间质量门禁的差异须明示：被拒绝的清单阻断其最终调用，现有覆盖复核则可能继续复核完整但格式错误的首次提取；不拿跳过的机会补替代调用。报告两个阶段的实际用量、失败／未知／跳过及最终原始／接纳／拒绝结果。这改变多项流程任务，不是单一提示词变量；机会相同不代表 token、费用或耗时相同，也不证明稳定改善或独立语义验收。

### 5.3 实体优先、修订绑定的知识研究流程

该内部候选先提取实体与提及，持久化初始 `EntityAnalysis` 修订，再针对这一不可变修订请求知识。实体阶段研究 profile `knowledge-extraction-v35` 按顺序组合原始 strict30 字节、既有 v34 `entity-evidence-semantics-v1/rules.txt` 与既有 v33 `entity-task-only-ablation-v1/task-suffix.txt`，不新增示例或来源答案。它保留 prompt-profile v1 与普通 v4 提取 wire，要求原生响应 `proposals: []`。冻结 profile 是工程身份，不是提取质量成绩；宿主不能清空意外返回的 proposals。

`boundKnowledgeContext(entityRunId, model, profile)` 通过实际的原文单次 E run 及完整原生归档认证实体阶段：核对冻结 profile、来源／输入／请求／producer 身份和执行配置，要求 E/M 已接纳且无知识或拒绝项，再把原生接纳结果与真实持久化的初始修订逐项对应。即使实体分析后来已有新 head，也只选 E run 记录的该修订。任意目录投影或同名标签不是持久化证据；读取 context 不调用模型，也不修改 E 修订。

仅知识 K 任务使用独立的 `knowledge-bound-knowledge-system/v2`、`knowledge-bound-knowledge-input/v2`、`knowledge-bound-knowledge-wire/v2` 和 `knowledge-bound-knowledge-check/v2` 身份，输出名称为 `bound_knowledge_v2`。响应为 `bound-knowledge`／`schemaVersion: 2`，私有 receipt kind `knowledge-bound-knowledge-receipt` 也使用 `schemaVersion: 2`，原生外层容器 kind `knowledge-bound-knowledge-native` 仍为 `schemaVersion: 1`。实际输入含完整选定 excerpts、limitations 和只读实体／提及目录，以来源及不可变修订摘要绑定。本次直接替换私有 K v1，不提供 v1 reader、别名或迁移；历史包须使用各自冻结代码核查。任务、Schema 和请求身份变化要求重新冻结比较，不能复用旧结果或 receipt。

K v2 system 共享通用知识语义政策：具体工作记录仍仅作上下文，其中有据且值得复用的结论用实际主题对象表达；可独立取真的肯／否命题或语气不同的命题须分别表达。条件和例外留在其限定的命题中，不机械拆成独立陈述。保留来源支持的材料及关键条件、限制、归因、证据等级和事实时间未知，包括完成报告中仍可复用的诊断或定量案例。来源消息时间不是事实时间，助手报告也不是独立执行证据。这些政策要求不改变 strict30 或 E35 的冻结 runtime 字节，不是关键词过滤或宿主语义修补。

响应包含 `proposals`、`catalogGaps`、`materialAccounting` 和 `excerptAccounting`。每项目录 gap 含 `gapId`、`gapKind`、理由及精确锚点；`gapKind` 为 `catalog_blocker`、`identity_unknown`、`granularity_unknown`、`scope_excluded` 或 `context_only`。这些仍是未经复核的模型声明，不证明实体资格，也不授权扩充目录或追加调用。响应不能重写 E/M、伪造 v4 提取响应或 raw 提取 run、拼接目录或修补引文；目录本身及没有 gap 都不证明语义真实或完整。

每项 `materialAccounting` 含 `materialId`、`meaning`、精确 `anchors`、`dispositionKind`、由 `proposalId`／`statementId` 构成的 `statementRefs` 二元引用、可为 null 的 `reason` 及 `catalogGapIds`。`expressed` 要求非空陈述引用且理由为 null；`not_expressed`、`context_only`、`scope_excluded` 和 `undetermined` 要求陈述引用为空且理由非空。gap 引用须闭合到实际 gap ID。每项 `excerptAccounting` 含 `evidenceRef`、`materialIds` 和可为 null 的 `noMaterialReason`：每个选定 excerpt 恰好一行，列出材料 ID 且理由为 null，或 ID 为空且理由非空。每份材料须列入其锚点涉及的每个来源，不得分配给无关来源。这些行将模型决定暴露给复核；名称及 `context_only`、`scope_excluded` 标签不能证明来源支持的材料可以删除。

锚点保留精确 `evidenceRef`、`quote` 和可为 null 的 `occurrence`，在原文中按 UTF-16 解析，不裁剪或修补。对 expressed 材料，每个锚点须被实际接纳陈述经 evidence 链接到的 citation 完整包含；每条陈述引用须覆盖至少一个锚点，每条实际接纳陈述也须被 expressed 材料账目引用。宿主校验双向来源／账目闭合、精确位置及接纳 S→evidence→citation 的包含关系；不保证模型识别了全部材料、引用陈述实际表达了对应材料，也不保证含义或处置判断正确。`semanticStatus` 始终为 `not_reviewed`。

`importBoundKnowledge` 通过可选的可信只读 `boundKnowledgeArchive` 端口重新读取完整 receipt／native 字节，并重建当前 K 任务供同请求 producer 检查。认证来源／修订绑定、请求／配置及完整原生返回后，才使用既有 proposal 接纳与 `KnowledgeStore` 写入，将 grounding 绑定到 `entityAnalysisRef`。坏 gap／账目行、锚点或引用分别诊断，不丢弃独立有效的 proposal。UTF-8／JSON、版本／binding 或基本外层结构错误使响应 rejected；归档、来源链或认证异常仍为 STOP。原始返回完整保留，不由宿主扩充目录、修补引文或做语义 union。

导入器通过 `proposalAdmissionStatus` 单列 proposal 接纳轴，并报告 `coverageStatus: declared_only | unresolved | unavailable`。材料为 `not_expressed`／`undetermined`、存在前三类 gap，或 gap／账目结构、位置、引用有问题时，coverage 为 `unresolved`，组合结果为 `partial`，即使全部 proposal 已接纳。有效的 `context_only`／`scope_excluded` 声明本身不阻断；被拒绝的响应无法提供可用覆盖账目，报告 `unavailable`。`declared_only` 仅表示声明及位置对账没有未决诊断，绝不是覆盖通过。返回的 `committed` 项保留原生 `proposalId` 到实际知识／修订身份的对应。proposal 接纳及这些覆盖状态都不代表完整业务成功或语义验收；不创建公共提取 run 或质量框架，也不把 K 计为第二个实体 run。

E 成功、K 失败时保留 E。导入中断后重放原 receipt，按 receipt ID、proposal ID 与 role 导出相同的私有 `knowledge-bound-import-ids/v1` 知识、修订和存储 request 身份。既有存储幂等性允许重放相同内容；同一组 ID 下改变内容不能覆盖先前写入。重放继续读取同一初始 E 修订与 K 归档，不增加模型调用、不跟随更新的实体 head，也不修改原始 native 证据。K v2 不迁移已写入的 `KnowledgeStore` 内容或 E 修订。

普通 strict30 默认、v4 wire、`knowledge-generation-single/v1` 生成策略及公共存量格式／数据保持不变；普通宿主不安装该研究归档端口，也不默认选择 v35。复用 v33 后缀不意味着该流程是 v33 前驱，更不授权绕过既有覆盖复核前驱契约。K 使用自己的任务和回执，不把响应伪装为失败或空知识的 v4 提取。

新的前瞻诊断仍须冻结完整 E+K 流程：实际来源／profile／配置、初始修订及原生引用、依赖 K 输入、顺序、调用机会、停止规则和最终端点。复核全部 E/M 与知识、来源支持的信息保留、每项 gap／账目声明、部分／失败效果及两阶段实际 token／cache／费用／耗时，未知用量保持未知。不复用旧分数，也不因来源未变而声称新独立证据。任务和绑定变化不是单一提示词变量对比；E 阶段空知识、编写的回归或 CI 绿色不能证明业务质量、生产采用、泛化能力或 #1322 要求的独立真人验收。本契约说明不代表 v2 真实模型诊断已经运行或通过。

### 5.4 独立实体任务与接纳边界

显式选择的 `knowledge-extraction-v36` profile 独立重写 E-only system，不拼接 strict30／E35、知识生成要求或完整 Schema。执行器仍提供不变的 v4 structured wire；prompt-profile v1、已持久化策略／Schema 契约及生产 strict30 默认保留原有身份与字节。完整 system 的原始 UTF-8 SHA-256 为 `8e8d93d11cf2bf6b4cfc2e419d95bfe61043c5ecf92282446482e9bb39436e4c`，已登记的 v36 不能标识其它字节。运行时 `run.promptHash` 使用 canonical JSON 哈希，与该原始摘要分别检查。任务还绑定精确的 source-only 输入、当前 structured wire 与 `knowledge-generation-single/v1`，不接收覆盖复核或来源清单输入。

原始 native 返回归档并保留 raw 输出后，宿主在准备接纳或首次写入实体／知识修订前，检查任务身份及显式 `proposals: []` 要求。非空 proposals 数组即违反任务，即使其中各项无效或原本会被拒绝。任务越界使 run 以 `entity_only_task_violation` 失败；宿主不删除 proposal、不修补实体，也不再次调用模型。原始 run 与 native 证据仍可查阅。普通解码／原生失败沿用各自的既有失败路径。

恢复 prepared 状态的 v36 run 时，重新读取同一份已归档 native outcome，将其 raw 输出与已保存 run 核对，并在继续写入实体或知识前重新执行任务／身份检查。prepared 状态不能凭看似为空或被编辑的 proposal 投影绕过拦截。该恢复检查保留原始返回，不迁移或重新解释历史任务，也不撤销此前已持久化的证据。

重写 system 与任务接纳边界对该候选构成 **BREAKING-COMPARABILITY**。真实诊断前须独立冻结来源／模型／输入／runtime、调用机会、停止规则及费用统计口径；执行后记录实际 token／cache／费用／耗时，未知费用保持未知。v36 不继承 v35 或此前 E/R/K 诊断的分数。拦截仅证明任务范围受限，不证明漏提、类型判断、提及 rationale、语义错误率或独立真人验收已改善。历史输出、冻结包和分数保持不变。

### 5.5 来源派生的提及定位目录候选

显式选择的内部 `knowledge-extraction-v37` profile 保留 E36 的实体语义，增加 `knowledge-body-occurrence-guide/v1` 使用说明。完整 system 的原始 UTF-8 SHA-256 为 `06568758fa41d4763c7c5f819c93cc5859f8a70aa661f3b4bd38499d52feba79`。固定输入保留全部原始 excerpts、元数据与 limitations，并增加 `occurrenceGuide`；派发、接纳、prepared 恢复和 E 到 K 的前驱检查都重建同一份输入。v36 的空 proposals 拦截也适用于 v37。普通宿主不选择这两个 profile；strict30 默认、原始 v36 字节、v4 wire 和公开存储／CLI 契约保持不变。

目录仅覆盖 `github_issue_body` 与 `github_issue_comment_body`。候选词形是完整的最大 `[A-Za-z0-9_$-]+` 连续段，首字符须为 `[A-Za-z_$]`，长度为 2～64 个 UTF-16 code unit；仅保留在该选段内有多处精确匹配的引文。匹配包含重叠及其它标识内部的同形子串，不声称这些位置都是语义提及。每个位置为 `[occurrence, start, end]`，序号在整个选段内从零连续计数。逐字上下文向两侧各延伸最多 24 个 code unit；重叠或相邻区间共享原文面板。面板可包含比单个位置更多的上下文。原始证据仍是依据，未收录引文仍可选择，模型 selection 仍仅含 `evidenceRef`、`quote`、`occurrence`。

构建必须完整成功。固定窗口上限为 1,024 条选段、1,048,576 个来源文本 code unit、512 对候选词形／选段、256 行重复引文、4,096 个位置、65,536 字节目录 UTF-8 序列化结果及 4,194,304 个逻辑工作单位。输入检查、扫描、比较、匹配、面板构建和序列化都计量；拒绝时不返回局部目录。应用在检查 producer、创建 run 或派发模型之前抛出 `ExtractionOccurrenceGuideError`，不截断也不回退。逻辑工作与分配计数仅是诊断边界，不保证 CPU、堆内存、耗时或模型上下文；原生辅助函数内部及外层输入构建不在该计数内。原有 system 加 input 字节容量检查仍然生效。

正式 extraction study/v1 每个 case 仅有一份两臂共享输入，明确拒绝 v37，恢复计划时也同样检查。私有诊断须使用真实应用任务，事前分别冻结两臂的不同输入。这构成 **BREAKING-COMPARABILITY**：说明与输入同时改变，不能单独推断目录的因果效果，也不能继承旧分数。比早期离线目录更小的输入、精确位置检查和工程门禁通过，都不证明漏提减少、rationale 正确、模型可用性、泛化或独立真人语义验收通过。

### 5.6 来源清单、实体发现与提及绑定

这一私有研究入口组合三份分别归档的原生任务：当前 source-plan（system v3）、A（`entity-discovery`）与 B（`mention-binding`）。A／B system 各为 v4，input、wire、check、response 与 receipt 各为 v2，输出名称为 `entity_discovery_v2` 与 `mention_binding_v2`；原生归档外层容器仍为 schema v1。source-plan 保留 input／wire／schema v2 与不变的检查器；其 system 变化和下游请求绑定边界见 §5.2。A 接收完整选定来源及完整、已认证的清单，再固定实体目录、指代范围和身份假设。精确 quote／occurrence 锚点提供来源依据，不是最终提及；组件和集合的证据先引用这些锚点，等待 B 创建实际提及。

A 完整接收与独立 v36 实体任务逐字共享的七种所指层次规则，带入既有含义和依据门槛，包括一般操作概念与某次实际或计划执行、配置对象与有来源系统／模块组件的区别，以及缺少细层次依据时用 proposed `object` 并明确保留类型未知。Schema 枚举本身不提供这些语义。v36／v37 及生产提示词字节继续冻结；本次 A system v3→v4 构成 **BREAKING-COMPARABILITY**，v2 wire 与持久化 Schema 不变。规则完整传递不证明模型类型判断正确。

A 必须在 `dispositions` 中通过 `sourcePlanObjectId` 恰好处理每个清单 `objectId` 一次：`retained` 对应恰好一个 A 实体，`corrected` 对应一个或多个，`excluded` 或 `undetermined` 不对应实体。每行提供理由和精确来源选择；重复、遗漏或未知 object ID、非法目标和非法选择均拒绝。拆分或多个清单对象映射到同一实体时，必须使用 `corrected` 处置并给出来源依据。A 仍可依完整原文独立发现并增补对象，清单不是封闭候选集。清单的 `planningRole`、资格／层次依据与不确定性仍是不可信模型判断：候选标签不强制保留，上下文标签不授予删除许可。须依来源区分操作与产物、配置与其控制的机制、产品与其执行的过程，不为每个名词或动词造实体。

宿主检查逐 ID 处理账目完整性、引用闭合和精确位置，不判断排除、纠正、身份或类型是否语义正确。合法 `undetermined` 行仍是 checked 响应，显式保留 `dispositionIssues`，但禁止构造 B 或导入分析。它与有据的实体身份未决不同；后者继续通过既有实体契约表达。仍须复核完整原文的遗漏：显式处理能暴露已列对象的静默丢失，不能发现清单自身漏掉的一切，也不能证明清单对象确实指向必需所指。已知有界集合可以保留未知成员，不因此把组身份改成未决。

B 收到同一完整来源及 A 的完整已认证回执、原始响应，其中包含绑定的清单身份与处理账目。输出只能含提及及身份支持映射，不能新增、删除、合并、改名、改类型或以其他方式编辑 A 实体。它重建含清单的精确 A 输入，不接受仅含原文的前驱。先判断提及资格，再判断目标：有独立资格依据、但被 A 遗漏或保留未决的所指提及仍为显式缺口；普通符号、参与者、结果或泛称不因目录缺项自动获得资格。歧义和未绑定提及继续显式保留；宿主用精确 quote／occurrence 计算 UTF-16 位置，不从 A 锚点补造提及。

B 还完整接收与生产提示词逐字共享的提及边界规则。有来源的完整名称或限定描述可以指向对象，无关谓词、结果或属性归属短语不因此成为对象的别名；须区分对象的实际指代与关于它的陈述，不追求最短字符串，也不机械裁剪后缀。按选中原文跨度重新计算 occurrence。本次 B system v3→v4 构成 **BREAKING-COMPARABILITY**；生产、v36／v37、A 提示词字节及全部 v2 协议／存储 Schema 保持不变。宿主继续检查位置与引用闭合，不判断自然语言提及资格或修补跨度。

读取 A 之前，应用先通过既有只读 `sourcePlanArchive` 端口认证固定的清单引用。缺少清单访问能力、来源不可用或不匹配、清单证据无效，均在读取 A／B 之前停止。随后发现归档边界按该清单认证 A；完整前驱链认证通过且没有未决处理项后，才能构造 B。三阶段使用相同 executor、model、timeout 与输出 token 设置，receipt／attempt 身份各自不同，要求完整单轮、无工具、无内部重试或子代理的原生返回，并按先清单、再 A、再 B 的顺序执行。每个完整原生 outcome 都先归档、后认证或解释。失败、拒绝、cleanup 失败、证据缺失或结构拒绝不预留修复调用。三份原件分别保留，不伪装成复合 `ExtractionRun`。

接纳继续采用全有或全无：每个 A 实体必须有位于自身来源锚点内的实际 bound 提及；每个组件／集合声明恰好对应一项支持映射，只引用位于对应锚点内的 bound 提及，且至少一条归属于该实体。未决处理项、歧义或未绑定提及、支持缺失、非法引用及既有实体接纳检查中的任何拒绝，都会阻止整个初始分析，不用合法子集替代 A。可接纳时原样复制 A 元数据，将支持引用映射到 B 提及 ID，再一次写入既有 `EntityAnalysis` schema v2。同一 B 回执的逻辑 ID 保持稳定；写入身份显式绑定清单、A、B 三份回执的字节引用及导入者 actor。重导入重新认证三份原件，不调用模型，复用原修订时间，由存储检测证据变化或命令冲突。

含清单绑定的 A／B input／wire／response v1→v2 替换构成 **BREAKING-SCHEMA** 与 **BREAKING-COMPARABILITY**。当前任务身份继续沿用既定的当前版本 reader 策略，不提供旧 reader、别名或迁移。历史原件、回执、冻结运行时、输出分数和已写入的实体／知识历史保持不变；历史包（包括 A／B system v3 证据）使用匹配的冻结代码核查，不由现行 reader 重新解释。该边界仅作用于私有研究证据，不迁移公共工作区存储，也不改变既有落盘实体身份。

普通宿主不安装这两类研究归档端口。生产 strict30、v4 提取 wire、既有 run／存储格式与 CLI／Studio 路径保持原样。既有单 E 前驱契约不接受这份三原件分析进入 E→R/K，正式 extraction study/v1 也不表达此流程。后续诊断须在解释结果前冻结三任务、来源、运行时、实际依赖输入、调用机会、停止规则和最终端点，分别报告每阶段的实际用量、缓存、费用、耗时、失败与未知。增加清单同时改变任务输入和总执行成本，不是仅改变 A 的提示词对照，不能继承旧分数或证明历史遗漏发生在哪个环节。工程检查不证明语义正确、召回率、稳定改善、泛化或独立真人验收通过，全部检查保留 `semanticStatus: not_reviewed`，真人复核仍单独进行。

### 5.7 有限目录修订与提及重绑定

这一显式选择的私有流程在当前 base3 链——source-plan system v3、A system v4 与 B system v4——之后增加 A′（`entity-refinement`）和 B′（`mention-rebinding`）。两个新任务的 system、input、wire、check、response 与 receipt 分别采用独立 v1 身份。首版只接受当前 base3 身份，不为历史初始链提供兼容 reader 或迁移。该变化构成 **BREAKING-COMPARABILITY**，不继承 base3 或此前分数。初始 B 只要结构 checked，无论接纳 ready 或 blocked 均可进入修订：ready 不证明语义正确。原生或结构失败不构成修订机会。

模型输入是完整选定来源与所需原始响应的平坦投影。A′ 完整接收未修改的 source-plan、A 和 B `rawOutput` 各一次；B′ 另外完整接收 A′ `rawOutput`，同样各一次。输入不递归嵌套 `receiptRaw`，完整回执、原生 outcome 与请求仍分别归档。构造依赖任务前，宿主认证全部已有前驱；最终导入和重放重新认证五份原件，包括精确请求、来源、配置、producer 见证、时间顺序及各自不同的 receipt／attempt 身份。缩小模型投影不放宽这些认证。容量须在 claim 前检查，不截断、不提供局部输入或静默回退。

A′ 返回完整替换目录与 anchors、全部 source-plan 对象的处置，以及每个旧 A 实体的完整账目。每个旧项均有明确的 retained、corrected、excluded 或 undetermined 处置，并在适用时给出目标映射；遗漏不等于排除。纠正和排除须有理由与逐字来源依据。新增对象须有独立来源支持。来源中真实存在的未消解所指仍可按实体身份契约表达；仅为让绑定成功而创建占位对象，不证明对象存在或未知已消除。

B′ 向固定 A′ 目录绑定实际提及与身份支持，并完整交代每个旧 B 提及和支持的去向。retained 提及保留实际原文跨度和到新结果的显式映射；corrected 或 excluded 项须有逐字来源依据，不能静默删除。支持映射须引用实际返回的提及。未决处置、未绑定或歧义提及、账目缺项、非法映射或任意接纳拒绝，继续阻断整个最终分析。宿主不裁剪跨度、不从 anchors 补造提及、不强绑，也不接纳合法子集。

driver 在执行前固定机会和停止规则：最多各一次 A′、B′，不隐式调用模型、重试、替补或无限修补。依赖输入由已认证的归档前驱物化，并在各自 claim 前固定。每个完整原生 outcome 都先归档、后解释，失败或 blocked 原件也保留。初始链与中间 A′ 结果均不写分析。只有最终 B′ 组合 ready 时，才一次写入初始 `EntityAnalysis` schema v2，使用新 ID namespace，并从 B′ 回执派生稳定身份。command／actor 身份绑定完整五原件链摘要。重新导入认证同一链并复用相同写入意图，证据变化不能覆盖原写入。

历史原件、冻结运行时、结果及既有实体／知识历史保持不变。生产默认、public exports、公共存储契约与 CLI／Studio 路径不改变。既有单 E→R/K 入口不接收三原件或五原件分析；五原件流程另有 §5.8 中显式选择的独立认证交接入口。没有 K 时，不能提供知识保全验收证据。

完整账目、精确位置和来源选择让决定可复核，不证明保留、纠正、排除、资格、身份或类型语义正确，也不证明原文没有遗漏。新的前瞻诊断须冻结五任务构造、实际依赖输入、来源／运行时／配置、机会、停止规则和最终端点，分阶段报告实际用量、费用、失败与未知。有限修订改变流程和总成本，不证明稳定改善或单一提示词因素效果。全部结构结果保留 `semanticStatus: not_reviewed`；#1322 的独立真人验收仍单独进行，满足其要求前保持 `goldReady=false`、`formalReceipt=false`。

### 5.8 修订后的可选认证知识交接

私有 `refinedBoundKnowledgeContext` 与 `importRefinedBoundKnowledge` 入口支持五原件→K；`refinedReviewedKnowledgeContext` 与 `importRefinedReviewedKnowledge` 支持五原件→R→K。它们是单 E 前驱契约之外显式选择的独立路径，不扩展该契约可接受的输入。context 准备与 import 只认证归档证据，不调用模型，也不伪造 `ExtractionRun`；独立执行的 R、K 任务各自保留归档原生 outcome 和回执。

每次读取 context 和 import 都重新认证 source-plan、A、B、A′、B′，要求最终组合 ready，且已作为初始实体修订落盘。该修订及写入回执的完整规范化字节必须与重建的写入意图一致，包括原始来源、完整链、导入者 actor，以及稳定的 analysis／revision／entity／mention 身份。较新的实体 head 不能替代初始修订。证据缺失、blocked、变化或不匹配即停止交接，不接纳子集，也不复用此前返回的 context 绕过检查。

R、K 保留既有 prompt 字节、Schema 与接纳规则。输入通过既有投影使用完整原始来源和最终已存实体／提及目录，不将此前清单、目录响应或 AI 复核主张提升为来源证据。R 开始时间不得早于 B′ 完成；经过 R 的 K 不得早于 R 完成，直接 K 不得早于 B′ 完成。五原件及所选 R／K 阶段的全部 receipt、attempt 身份必须各自不同。每次 import 都在知识写入前重新读取并认证完整前驱链及所选 R／K 证据。

知识导入沿用既有逐 proposal writer，以及从 K 回执、proposal 和 role 派生的 `knowledge-bound-import-ids/v1` 身份。同级 proposal 被拒绝或覆盖账目未决时，已接受 proposal 仍可写入；整个响应被拒绝时不写入。这不是批量原子操作：中断时，较早 proposal 的写入可能已提交。重放同一归档证据时重新认证链，并复用相同 store request ID，不产生新原生调用；内容冲突不能覆盖原写入。K 失败不撤销初始实体修订或已提交知识。

增加 R／K 改变流程拓扑、依赖输入、调用机会和总成本，构成 **BREAKING-COMPARABILITY**。前瞻诊断须冻结所选完整路径及端点，分别报告每阶段实际用量、费用、失败与未知；不继承旧分数，也不重判历史研究。认证、接纳、重放和保存成功不证明真实模型质量或知识保全验收通过。结果继续为 `semanticStatus: not_reviewed`；#1322 的独立真人验收仍单独进行，满足其要求前保持 `goldReady=false`、`formalReceipt=false`。生产默认、public exports、既有存储契约及数据保持不变。
