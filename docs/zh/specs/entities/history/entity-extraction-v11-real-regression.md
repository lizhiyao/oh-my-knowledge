### 已观察到的目标行为

首个窗口的 `p2/s7` 使用 descriptive／negative 否定“需要修改以解决本轮 Session 计数差异”，保留 API 总数 1 与概览页叠加显示 2 的来源解释。它没有把“无需修改”升级为禁令，也没有推导实际是否修改。`p1/s1` 与 `p1/s2` 分别表达初始化计数的正向要求及状态更新不增加分母的负向要求。

master 采用预先允许的 version，提交号和所属组件未知，结果限定本次被测状态。`p3/s8`～`s11` 分别保留两个代码状态的计数结果、重复 flush 未重复发送及 master 改造尚未发布；不补逐版本调用记录，不外推未来 master。

第二个窗口的 `p3/s9` 明确保存字段值为字符串 `unhandled`，context 保留 MiniappClient、core 11.4、浏览器类宿主与小程序范围，以及 JS 未处理异常不等于进程崩溃的来源理由。来源合理性判断仍为 source_assertion；没有用字段名、qualifiers 或可回查引文替代配置知识，也没有补运行机制。

这些是本批新输出的观察。与旧 v8 缺口相比，目标内容本次已出现；没有同期 A/B，不能把差异归因于提示词，也不重算旧报告。
