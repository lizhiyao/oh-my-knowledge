# 实体提取质量验收

状态：P4 的检查工具与标注草案。指南 `omk-entity-annotation/v1`，语料 `omk-entity-quality/v3`，检查 `omk-entity-critical-checks/v2`；适用于 `knowledge-extraction-v4`／响应 Schema v4。**独立人工复核与新模型验收尚未完成。** [Issue #1127](https://github.com/lizhiyao/oh-my-knowledge/issues/1127) 保持这两项待办。

## 1. 版本与适用范围

本指南采用[实体身份规则](./entity-identity.md)及[实体提取契约](./entity-extraction.md)。旧 `v2` 语料、`v1` 检查、v3 提示词报告和原始输出保持原样；新口径不重算旧报告，不能直接与旧计数比较。这是 `BREAKING-COMPARABILITY` 的新测量身份，不改变生产提示词、Schema 或用户存储。

`test/fixtures/entity-extraction-review.json` 是公开的合成草案：8 个开发窗口、8 个预留验证窗口，共 50 个关键提及。按项目和会话隔离，并拒绝跨集合的重复消息窗口。覆盖中文、英文、代码、重复名称、共指、晚到纠正、环境、实例、版本、集合及来源截断。它不是隐藏的盲测集，也不代表真实日志分布；验证窗口不得用于提示词调参。未来真实语料另行最小化、授权、分组和复核，不能把合成窗口混入真实日志分母。

## 2. 标注单位与允许表达

先冻结来源消息、角色、缺失记录及窗口限制，再逐项标注：

| 标注 | 规则 |
|---|---|
| 关键提及 | 标注对检索、身份或知识理解必要的名称和指代；不是标全体名词。保留消息序号、原文和从零开始的出现序号；重叠匹配计数，位置为 UTF-16 半开区间。 |
| 允许边界 | `alternatives` 只能列出输出前已确认的等价边界，例如完整代码标识含或不含反引号。不能用任意包含该名称的大段引文充当命中；边界扩大仅列为待复核候选。 |
| 身份组 | 同一个 `entityKey` 的提及必须归并，不同身份组必须分开。模型 ID 和标签不作答案；通过原文位置对齐后比较提及对。 |
| 层次及关联 | 标明允许的 `referentKinds`、身份状态、明确候选、组件和集合成员／完整性。只有指南允许的表达才能作为备选；来源不明时保留未知。 |
| 知识角色 | 先标来源锚点、主体、对象和解释。自然语言关系允许同义表达；语义、方向、否定、条件、时间和纠正由人工按全文判断，不能用关键词缺失判错。 |

集合指代是一个集合提及，不能复制为多个成员的同跨度提及。实例／版本与组件分开；仅改变环境条件不强制拆身份。工具和日志、计划和执行、删除后新建与改名分别处理。同名或相同路径不足以归并。确实存在两种合理身份方案时，先裁决，或在输出前显式表达允许方案；当前草案不支持多个相互冲突的身份分区，争议未解决的案例不能冻结。

## 3. 分层结果与通过门槛

| 层次 | 程序记录 | 判断限制 |
|---|---|---|
| 调用与捕获 | 调用失败、JSON 解析失败、取消、未尝试分别计数。 | 内部检查器异常立即停止，不能伪装成模型失败；不重试隐藏失败。 |
| 结构接纳 | 响应顶层 Schema 拒绝、提及／实体／知识拒绝及逐项原因。 | 合法 JSON 的结构拒绝仍是已捕获输出；不得记入 `capture_failures`。拒绝条目数含级联后果，不能当作互相独立的错误数量。 |
| 关键提及 | 严格边界命中／遗漏／歧义、扩大边界候选、关键提及 recall。 | 未穷尽标注，所以 precision／F1 为 `null`；额外提及需要人工判断，不能直接算误提取。 |
| 身份 | 提及对的归并／分离、错合并／错拆分；层次、候选、组件与集合的差异。 | 未对齐提及及缺失引用标为 `not_evaluable`，不能算通过。提及对相互相关，计数不是独立样本准确率。 |
| 知识关联 | 只列来源锚点关联的陈述及端点；反向端点给出待复核提示；没有陈述为 `not_observed`。 | 端点匹配不证明关系或陈述真实；同锚点的其他陈述、宽引文和同义表达必须人工复核。 |
| 独立语义 | 按每例 `semanticChecks` 核对条件、时间、否定、主张／观测、计划／完成、案例组织及晚到纠正。 | `optional` 允许没有知识；遗漏与错误不同。`none` 场景生成知识需登记问题。空结果不能证明知识关联可靠。 |

冻结后的本合成关键回归门槛：所有计划调用有记录；无调用／解析失败、取消、未尝试或结构拒绝；关键提及命中率 100%；所有应归并／分离提及对和身份关联匹配，无 `not_evaluable`；已生成知识的角色、条件和状态全部经独立人工复核，无未裁决问题。可选知识没有生成时，只能判断实体项，知识关联覆盖仍不足。当前工具不自动判定整个门槛通过，始终保持 `semanticReview: pending`，报告未验证范围。

这是一组限定边界的回归门槛，不是总体质量百分比。重复两次最多提供两份样本；两轮全部通过也不能称为总体稳定性或跨 Agent 收益验证。真实日志的抽样与门槛另行预定，不能事后用其结果调整此门槛。

## 4. 独立复核、争议与冻结

1. 实现者／作者先做来源闭合、位置、分组与契约自检，生成复核包。该步骤是自审，不计入独立复核。
2. 与作者独立的人逐例检查指南、允许边界、身份组、角色及语义标准；在 `review-template.json` 填写每例 `approved` 或 `changes_requested`、理由、复核人、时间和独立性声明。独立模型评委不等同于独立人工复核。
3. 争议在看到输出之前裁决，记录问题、结论和独立裁决人。未解决时使用 `changes_requested`。需改语料／指南／检查器时升级相应版本并重新生成复核包，不能靠修改复核记录批准旧摘要。
4. 复核记录必须覆盖全部案例，绑定测量身份，并早于输出捕获。检查器拒绝作者自称独立、缺项、错误摘要和事后批准。它只能验证声明与记录闭合，不能验证复核人身份真实或保证其判断正确；`attested_independent_human` 表示有声明，不是效果结论。
5. 测量身份由语料、双语指南、已编译检查器及生产运行产物摘要、依赖清单／锁文件摘要、Node 版本、提示词原始 UTF-8 摘要和版本组成。重建改变产物字节也会改变身份；冻结后保留同一构建用于验收。复核包分别保留中英指南原始字节及便于阅读的合并稿。运行时 promptHash 的规范化 JSON 摘要与这里的原始 UTF-8 摘要不同，不能混用。

## 5. 离线复核工具与证据

先更新编译产物，然后生成外置复核包：

```bash
yarn build:runtime
node dist-scripts/bench/entity-extraction-review.js \
  --corpus test/fixtures/entity-extraction-review.json \
  --output /private/tmp/omk-entity-review-unique
```

输出目录必须绝对、在仓库外、父目录存在且目标未存在；即使通过软链指向仓库也拒绝。工具保存原始语料、双语指南、位置与答案展示 `review.html`、复核模板、模型输入及摘要、测量 manifest。未提供复核记录时 `goldReady: false`。模板默认需要修改且未签署，不能不经填写就批准。

可选 `--review /absolute/review.json` 校验复核记录；可选 `--captures /absolute/captures.json` 只检查已有捕获。本命令**没有执行器入口，模型调用数始终为 0**，生成包或签署标注不授权数据发送或模型执行。

捕获格式 `omk-entity-captures/v1` 包含同一 `measurementId`、单一 split、1 或 2 次计划重复、开始时间、执行器和模型，以及 `caseId`、重复序号、冻结输入摘要和结果。结果为 `output`（原文与可选原始 usage）、`call_failure` 或 `cancelled`，可记录执行器实际报告的 `durationMs`、`costUSD`；未知值省略，不补零。检查未知／重复／超计划记录及输入摘要，完整保留原始捕获和接纳结果。未尝试记录逐项保存；没有完成检查的关键提及不进入命中分母，另列未检查数。只汇总已报告的用量、耗时和费用；任一已记录尝试未报告费用时总费用为 `unknown`，同时显示已报告部分，不能推测费用或将部分覆盖称为整轮成本。

结构拒绝不让捕获状态变成失败；调用／解析失败、取消或未完成计划使命令非零退出。程序成功退出仅说明离线检查完成。原始输出与逐项接纳、原始 usage 和全部失败均保留，报告继续显示语义复核待完成。P5 再在具体授权范围内执行模型验收，并取得逐项独立输出复核。
