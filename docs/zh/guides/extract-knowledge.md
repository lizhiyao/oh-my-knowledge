# 从工作日志提炼候选知识

从一份明确选定的 Codex JSONL 日志提炼事实、案例或方法，然后逐条核对实体、适用条件与原始记录。候选始终等待复核；保留表示愿意维护，不等于内容已证实。命令不会自动修改 AGENTS.md、skill 或其它生效载体。

## 选择来源并生成

明确指定本地知识工作区；CLI 与 Studio 使用同一目录。以下路径和身份均须替换为自己的值：

```bash
omk observe knowledge capture --workspace ./knowledge --source ./session.jsonl --json
```

可用 `--start-record 10 --end-record 30` 限定范围。序号从零开始，只计非空行，起止均包含。先核对输出中的 `snapshotId`、记录范围、片段与限制。`capture` 只在本地归档，不调用模型。

```bash
omk observe knowledge source --workspace ./knowledge --snapshot <snapshot-id> --json
omk observe knowledge generate --workspace ./knowledge --snapshot <snapshot-id> --executor codex --model <model> --json
omk observe knowledge list --workspace ./knowledge --json
```

生成发送归档中的选定片段与覆盖限制，使用明确配置的执行器和模型，可能产生费用。支持 codex、openai-api、anthropic-api；其它执行器尚未提供此入口。凭证配置沿用对应执行器。原始日志路径和原始记录封装不作为生成输入，但选定片段本身可能包含敏感内容，应先核对。

日志由本地 Node 读取和解析，模型只接收整理后的选定片段；CLI 与 Studio 共用这一应用流程。Codex 在空临时工作目录运行，沿用执行器的只读 sandbox、忽略用户配置和规则的调用参数，并要求不调用工具。若实际发生工具调用，本次输出不接纳；这不是禁止所有文件访问的强隔离保证。API 请求不提供工具。

当前生成使用 `knowledge-extraction-v3`，一次调用返回独立实体分析和引用共同实体的知识候选。模型提供指定片段的逐字短语，可附紧邻前后文；程序唯一定位后计算 UTF-16 位置，不修饰原文、不跨消息寻找替代依据。无法唯一定位时拒绝对应提及或依据；不合法实体不能支撑知识候选。条件、反例、后续纠正及未验证环节的实际保留效果仍需逐条复核。

v3 改变提示词、模型输出与身份分配范围，属于 `BREAKING-COMPARABILITY`：接纳数量变化不能直接解释为知识质量提升。当前只支持知识历史 v2、提炼运行 v3 和 `knowledge-extraction-v3`。旧格式不读取、不恢复、不迁移，文件保持原样；选择空知识目录，从原始日志重新提炼。当前运行保留原始输出，另存程序计算的位置，恢复不重新调用模型。详见[当前存储契约](../specs/entity-extraction.md#_6-当前存储契约)。

允许零候选，部分输出不合法时保留拒绝原因。引用匹配只说明位置存在，不能证明陈述为真。来源中的行为、他人说法和提炼推断分别呈现；未知时间与条件不补成确定事实。

## 核对与处理

```bash
omk observe knowledge show --workspace ./knowledge --id <knowledge-id> --json
omk observe knowledge retain --workspace ./knowledge --id <knowledge-id> --revision <revision-id> --generation 1 --reason '后续处理本项目时参考'
```

从最新 `show` 结果读取修订身份与 `history.generation`。`discard` 使用同样参数，记录舍弃理由，不删除历史。并发修改导致版本冲突时，重新读取并核对差异，不能盲目重试旧内容。

修订输入只包含 `title`、`content`、`entities`、`evidence`，可从 `show` 的 `revision` 中取这四项保存为 JSON。修改标题、陈述、上下文或证据解释后执行；绑定实体分析的知识须通过下一节修改实体名称或对应：

```bash
omk observe knowledge revise --workspace ./knowledge --id <knowledge-id> --revision <revision-id> --generation 2 --input ./draft.json --reason '补充适用条件'
```

使用实际读取的 generation，不照抄示例数字。修订生成新版本，旧内容和处理理由仍保留，新版本不继承旧版本的保留选择。原文位置继续绑定；新提及或实体必须在同一分析的原文中纠正，不能凭空填入引用。新来源窗口需要新的提炼。可用 `show --revision <old-revision-id>` 查看旧版本。

## 核对实体并应用纠正

```bash
omk observe knowledge entities --workspace ./knowledge --analysis <run-id> --json
omk observe knowledge correct-entities --workspace ./knowledge --analysis <run-id> --entity-revision <entity-revision-id> --generation <read-generation> --input ./entities.json --reason '根据原文拆分同名对象' --json
```

`entities` 默认读取最新实体修订，可用 `--entity-revision` 查看历史。纠正草稿只包含返回的 `revision.entities` 和 `revision.mentions`。已有身份保持不变；新增实体或提及使用唯一的 `new:<local-name>`，由宿主分配 UUID。同一提及身份不能换到另一段原文。提及必须精确引用所选来源；每个对象至少有一处有效提及。未知对象使用 `identityStatus: unresolved`，保留 `uncertainties`，可填写指向明确对象的 `possibleEntityIds`，不任选一个替代。

纠正实体保存新修订，不覆盖已生成的知识。将选定实体修订应用到知识时，先核对每条陈述的主体／对象；从实体修订取所引用实体的 `entityId`、`label`、`description`，写入知识草稿的 `entities`。拆分后明确选择新主体／对象，再执行：

```bash
omk observe knowledge apply-entities --workspace ./knowledge --id <knowledge-id> --revision <knowledge-revision-id> --generation <read-knowledge-generation> --analysis <run-id> --entity-revision <chosen-entity-revision-id> --input ./draft.json --reason '明确陈述中的对象' --json
```

此操作创建知识新修订并绑定精确的实体分析修订。默认保留原附加身份不确定性；可通过 `--identity-uncertainties '["核对后仍需保留的说明"]'` 明确更新，`'[]'` 清除原说明，当前实体分析中的不确定性仍自动保留。陈述中的条件与未知信息另在知识修订中核对。原实体分析、原知识及维护决定均可回看；新知识需重新决定保留或舍弃。仅限同一来源窗口，来源快照不可用时不能纠正或应用。独立实体结果允许零对象，也不要求同时存在知识候选。详见[实体提取设计与限制](../specs/entity-extraction.md)。

## Studio

### 对话自动提炼与项目待办

在对话页头选择**开启自动提炼**。先核对最近 3 个已结束轮次的初始消息，明确候选目录、执行器、模型和最多调用次数（1～20 次），勾选发送授权后选择**批准并开启**。美元费用未知，次数上限不是美元预算。打开预览不会调用模型。

授权仅限这一条对话，有效期 24 小时，且只在当前 Studio 服务运行时生效。之后每次最多处理 3 个新增已结束轮次，并带上前 2 轮上下文；记录稳定 30 秒后开始。进行中或状态未知的轮次等待结束；不读取整条历史来判断所有纠正。同一来源窗口不会重复发送，不能据此保证语义重复已经消除。失败或中断停止，不自动重新调用；**停止自动提炼**会取消本服务的进行中调用。停止时已产生的输出仍可能被保存。重启后需要重新开启；失败窗口如需重新生成，使用手动提炼并再次确认。

页头的**知识待办**显示待核对数量，点开即可在原页面保留、舍弃或修订候选，按需检查实体，再从已保留内容生成并保存载体。每轮的**提炼这轮**和页头的**提炼整条对话**继续支持手动选择消息，结果也可就地核对。项目列表提供相同的**知识待办**入口，汇集当前已索引项目对话的候选与处理状态；这是来源分组，不是知识归属、相似或冲突的自动判断。当前目录无法读取或尚无候选时直接显示相应状态。

调度权限与调用预留另存为当前知识目录下 `auto-extraction/<thread-hash>.json`，使用 `schemaVersion: 1` 和 `automationKind: conversation-knowledge-extraction`。调用前持久化次数和窗口摘要；预留计入额度，中断后即使未实际发送也不返还、不重新发送。每个 Studio 最多登记 32 个对话范围，串行调用；每条对话最多记录 2,000 个已结束轮次及 1,000 个已尝试窗口，超限停止。另以不可变的 `permission-<id>.json` 和 `attempt-<run-id>.json` 保留历次授权及每次调用与来源窗口的关联，不因重新开启而覆盖；目录最多 3,000 个文件。现有来源、知识历史、实体历史与运行格式不变，原始依据不覆盖。明确注入的完整 AGENTS.md 规则仅在阅读视图折叠，原文可展开，来源快照和发送预览仍保留原始消息。

启动 `omk studio`，使用命令返回的地址。一级“知识”直接进入“提炼的知识”，可搜索标题或标签，按待处理、已保留或已舍弃查找已有内容。“知识载体”分区先展示已保存的载体，体检与观测保留在同名标签页中。

阅读观测对话时，点击对应轮次的“提炼这轮”，直接确认这一轮的选定消息、保存位置和模型。在知识页点击“从对话选择”或“提炼新知识”，即可在当前页面选择对话和轮次；需要更大范围时可选择整条对话。消息调整和本次配置按需展开，确认“开始提炼”后才调用模型。成功生成候选后直接进入核对界面；没有候选、失败或取消时保留结果提示，可从“提炼记录”或对话的“知识待办”找回已保存内容。

也可在“更多”中导入本地日志文件，预览范围后再生成。保存位置随站内导航传递；“保存位置”只调整本次操作，长期默认目录在侧栏“设置与帮助”中修改，已有数据不会移动。

核对候选内容、适用条件和未知信息，再通过“查看依据”定位原文。窄屏可切换“候选内容／原始依据”；分类、时间和历史修订按需展开。填写理由后保留或舍弃，也可选择快捷理由并编辑；选择理由不会自动做决定。决定保存后自动进入本次提炼的下一条待处理候选，不会跳到其他提炼；可回看上一条或返回全部知识。修订生成新版本并留在当前候选，需要重新核对和决定。全部处理后显示本批保留与舍弃数量，并提供回看和返回来源对话的入口。“提炼记录”中的“核对本批候选”可重新打开该批已保存内容。

保留内容可从“知识 → 提炼的知识”重新打开。保留不会自动改写载体；点击“生成知识载体”才进入生成与保存。

提炼结果、提炼记录和对话的知识待办提供“核对实体与指代”，零知识候选也可查看独立实体结果。知识详情可打开绑定的实体修订。实体抽屉中核对名称、限定信息、歧义、提及对应及原文；可新增对象后重新分配提及以拆分，也可明确合并或删除误识别。选择来源消息并选中原文可补充遗漏提及。填写纠正理由后保存实体新修订，再在知识详情点击“应用实体最新修订”，核对每条陈述的主体／对象，保存新的知识修订。无需每次提炼先经过实体核对。

## 组织与检索知识

在候选详情的“主题标签”中编辑并明确保存标签。使用中文、字母、数字、下划线、连字符或 `/` 表示层级，不含空格，也不能只有数字；单条知识最多 32 个标签，每个最多 80 字符。重复标签不区分大小写。标签由用户维护，不额外调用模型，也不表示内容已验证；编辑标签不改变知识陈述、来源、修订或保留决定。

列表搜索支持标题与标签。输入 `tag:排障` 可匹配“排障”及“排障/证据判断”等子标签，并可结合处理状态筛选。标签用于组织主题，知识类型、适用条件和证据分类仍来自对应知识修订，不用标签替代这些字段。

标签历史单独保存到知识目录的 `tags/<identity-digest>.json`，使用 `omk-knowledge-tags/v1`，绑定知识身份，记录标签、修改时间与操作者。标签保存不改动知识、来源或运行记录。未设置标签时为空；并发修改拒绝旧 generation，读取后核对再保存。标签属于知识的组织信息，知识修订后仍保留，需核对它们是否仍适用。

## 生成并保存知识载体

在已保留候选或本批核对完成页点击“生成知识载体”，或在“知识载体”中点击“从已保留知识生成”。选择 skill 或 prompt、填写名称，核对所选的已保留知识，再点击“生成并核对内容”。初始选择只包含当前候选或当前批次的保留项；可明确增加其它保留项，单次最多 100 条。生成按已有内容组织文本，保留条件、例外、未知项、陈述与依据分类、原文摘录及来源版本，不额外调用模型。

生成时同时带出元信息快照：标题、摘要、主题标签、知识类型、场景、证据分类及精确知识／来源版本。摘要取自知识标题，场景取自陈述上下文，证据分类可包含多种类型；`verification_status: not_assessed` 表示本次生成不提供真实性或任务效果验证。prompt 使用顶部 YAML properties，`tags` 为列表，可供 [Obsidian](https://obsidian.md/help/properties) 等工具读取；skill 保持必需的 `name`／`description`，额外属性写入规范允许的 `metadata` 字符串映射，列表编码为 JSON 字符串。

元信息使用 `omk-knowledge-metadata/v1`，描述该版载体所纳入知识的快照，不是可回写知识库的管理入口。更新 OMK 生成的载体会重算这些属性；首次导入本地 prompt 时保留已有自定义字段和标签。标签在预览后变化也会拒绝旧预览。旧载体不会被后台改写，`manifest.json` 继续承担载体及知识修订关联的权威记录。

核对并编辑新内容后点击“保存载体”，会直接保存到当前知识目录的 `artifacts/<artifact-id>/vN/content/<directory-name>/SKILL.md` 或 `artifacts/<artifact-id>/vN/content/<directory-name>.md`，随后进入载体详情，显示实际载体路径、内容、来源知识和历史版本。显示名称支持中文；新载体的文件名称自动生成独立标识，skill 头部的 name 与目录名一致，保存时核对有效头部，遵循 [Agent Skills 格式](https://agentskills.io/specification)。无需复制粘贴到其它位置。来源链接定位到实际使用的知识修订。保存不代表内容已证实或改动已有效，使用前仍需检查适用范围并进行受控评测。

更新已有载体时，可选择已保存载体，或明确指定一个本地文件。生成预览保留原内容并追加新知识，可切换查看原内容，保存为新版本。基于本地 `SKILL.md` 生成时同时复制同目录的可分发资产，沿用既有过滤与内容摘要规则；原始文件不会被覆盖。知识保存目录不能位于被复制的本地 skill 内部，需要另选目录。已纳入的同一知识修订不会重复追加，旧载体版本保持可回看。回看旧版本时，需要选择最新版本才能继续生成更新。

每版 `manifest.json` 使用 `omk-carrier-v1`，记录载体身份、版本、保存时间、内容摘要、文件目录名、基线及精确知识修订关联。该目录是新增的载体保存契约，不改写候选、来源快照或既有评测数据。知识当前修订、保留决定或基线载体在预览后发生变化时，保存会拒绝旧预览，需要重新生成；外部修改的载体会标示内容变化。版本通过临时目录整体发布，失败或取消不会替换旧版。同机写入进程中断后，超过 30 秒的失效锁由下次保存恢复，并清理未发布的临时版本；不会抢占其它主机的锁。保存结果未能读取时先“核对已保存版本”，避免重复写入。

## 从载体验证改动

在载体详情点击“验证这个版本”。更新已有载体时自动带入原版本；新建载体可选择其它已保存版本或明确指定本地 skill 目录／SKILL.md、prompt 文件作为基线。两个版本必须形式一致且内容不同。选择本地用例文件或目录、执行器与固定模型，可配置模型评委，再点击“预览评测计划”。当前入口支持 1–100 个本地用例，不支持需要远程内容解析的用例。

预览展示两个版本内容、相同用例与评分依据、执行模型、实际评分模型及计划任务数量；不会调用模型。核对后点击“确认并开始评测”才开始运行，包括必要预检。费用无法提前准确估算，预检和模型评分可能增加调用；无自动重试。预览有效期为 15 分钟，载体、用例或运行计划变化时拒绝旧预览，需要重新核对。

“评测记录”关联精确载体修订和知识来源，保留结束、失败、取消及中断状态，可取消运行、打开原有 Core 结果与证据，再返回实际待测版本。取消不能撤销已经发生的调用或费用。启动响应未读到时先“核对运行状态”，避免重复调用；服务关闭取消其持有的运行，同机进程退出后的运行记录显示中断，不会自动恢复模型调用。已有 Studio 评测记录仍可访问。

这一路径以所选知识目录作为操作目录，Core 产物使用既有 `.omk/eval` 契约；新增 `.omk/state/jobs/carrier-measurements/<measurement-id>.json` 使用 `omk-carrier-measurement-v1` 保存预览与运行关联，不修改载体 `manifest.json` 或既有测量 Schema。记录可能包含所选用例与载体的私有内容，按本地数据管理。运行结束、载体保存或知识保留都不等于效果已验证；结论与证据范围以报告为准，生成用例需要复核，不能自动作为独立发布验证证据。

## Codex 版本检查

OMK 使用当前进程 PATH 中的 `codex`。先执行 `codex --version`；若服务器报告模型需要更新客户端，应升级或明确选择兼容的现有客户端，不必切换模型或 API。桌面应用与命令行可能使用不同版本。

## 中断与来源管理

`generate --run-id <UUID>` 可为一次运行指定稳定身份。相同请求重试不会再次调用模型；修改来源或模型时不要复用该身份。

```bash
omk observe knowledge runs --workspace ./knowledge --json
omk observe knowledge resume --workspace ./knowledge --id <run-id> --json
```

`resume` 只恢复已持久化输出的接纳或保存，不重新调用模型。若进程在保存输出前退出，记录可能仍为 generating；确认原进程已结束后，检查记录并以新的运行身份重新生成。失败或取消不代表完整候选已交付。

工作区含来源快照、候选修订及生成原始输出。它们可能包含私有内容，应按本地数据管理。`delete-source --snapshot <snapshot-id>` 删除来源快照并留下不可用标记，不修改原日志，也不擦除知识修订或生成输出中的引用文字；不要将它当作工作区的彻底清除。来源缺失、损坏或删除后，候选仍保留，但不能再声称原始依据可完整核对。

首次使用请逐条记录来源忠实度、适用范围、未来复用价值，以及误提炼、遗漏和修订原因。自动测试不能替代这项判断。
