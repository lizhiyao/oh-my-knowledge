# 核对知识质量

需要判断生成的知识能否保留、修订或用于后续任务时，按本页逐项核对。来源选择与操作命令见[提炼与维护知识](extract-knowledge.md)，使用前先核对其中的能力与版本边界。`quality` 的 `semanticQuality: not_assessed` 表示系统没有替你完成语义验收；保存、引文匹配与 retain 都不证明真值。

## 1. 固定来源与核对范围 {#scope}

生成前保存选定来源快照、版本、消息或记录范围，以及缺失、截断和未包含的材料。说明哪些认识、方法、条件或判断依据必须保留，哪些内容可选，允许怎样的等价表达，哪些歧义只能保留未知。根据实际用途提前确定错误、遗漏和可接受修改负担的界限。

需要比较改动时，还应固定模型、prompt／profile／wire 身份、运行配置、调用预算和停止条件。记录多个窗口是否来自同一对话，以及复核者是否已看过来源或输出。输出后新发现的检查项单列，不回改原分母，也不重算旧运行来制造改善。

输入没有提供的信息，先记为来源覆盖缺口；输入已有但生成正文省略的信息，才是提炼遗漏。不要要求模型补写来源没有的执行结果或项目事实。

## 2. 逐段核对完整含义 {#body}

先读完整正文，再回到精确来源。每个段落应能独立表达影响使用的含义，不能靠标题、附带引文、复用理由或实体目录补足正文遗漏。

| 核对内容 | 要回答的问题 |
|---|---|
| 重要认识、方法与理由 | 具体判断及其依据是否保留？方法的步骤、采纳前提和停止条件是否完整？ |
| 条件、例外与否定 | 是否扩大适用范围、丢掉反例，或把没有必要、没有禁止、尚未失败改成更强结论？ |
| 归因、立场与状态 | 谁提出、反对或接受了什么？建议、计划、临时处置和已完成结果是否分清？ |
| 时间与变化 | 来源消息时间是否被误写为事实时间？后续纠正是否保留历史背景，矛盾是否被无依据消解？ |
| 未知与证据 | 没有最终结果时是否仍为未知？来源主张、直接观测和推断是否分别表达？ |
| 主体与精确引文 | 引文是否支持这条主张及其主体，而非只命中同名词？正文的重要限定是否各有实际来源？ |

助手自述成功不自动成为直接观测；来源说法忠实也不等于已经外部证实。对每项判断留下精确知识修订／段落、来源位置、核对结果及理由。无法判断时记录未决，不把它计作通过。

## 3. 分开记录失败层次 {#failure-layers}

| 层次 | 记录与处理 |
|---|---|
| 正文 | 分开记录遗漏、误解、无依据扩写和归因／条件错误；对照原始返回与已保存正文，判断问题发生在哪一步。 |
| 实体与关联 | 核对对象含义、提及、目录修订及段落连接；不能凭同名确认身份，也不能用正确正文替错误关联背书。 |
| 来源定位 | 核对精确来源版本、连续引文及位置。定位成功不证明含义正确；来源不可用不等于空资料。 |
| 宿主接纳 | 查看阶段、拒收原因和派生投影状态；流程结束不代表所有投影成功。目录拒收与语义错误分别计数，不把级联影响当作多个独立根因。 |

派生关联失败时，已保存正文仍可独立阅读和维护。反过来，结构可读的关联也可能有语义错误，仍需核对。空知识、未生成、拒收、失败和未尝试的记录均应保留，不能只统计成功输出。

## 4. 纠正、保存并重开 {#maintenance}

正文修订与实体／关联纠正使用各自的入口。按[维护步骤](extract-knowledge.md)读取最新写头和 generation，保留精确来源及稳定段落身份，追加新修订；不要覆盖原始返回或历史决定。

新正文修订回到 pending，不继承旧 retain；核对后再对这个精确修订记录保留或舍弃理由。`reviewStatus` 与维护决定分开，保留仍不等于真实性认证。旧 body digest 的关联成为 `stale`，需要独立核对或重建，不能静默套用到新正文。

只改实体或段落关联时，核对原文、精确目录修订和投影 generation，再追加相应修订。重开检查当前结果及旧历史，确认正文没有被关联操作改写。接受一个投影不等于确认跨窗口同一身份或外部真值。

正文可以引用多个精确来源并继续维护；当前自动关联生成／重建要求单个精确可读来源窗口。多来源正文的自动重建受限时，保留可读正文和明确关联状态，不把它当作多来源图谱已完成。工具轨迹、直接项目文件与其它来源接入也应按实际支持范围区分。

## 5. 记录实际投入与复核范围 {#cost-and-review}

保留实际派发尝试、归档结果、阶段耗时、tokens 与执行器上报费用。说明输入计数是否包含缓存；缺失美元费用保持未知，不能当成零，也不推测 provider 内部请求数。阅读、回查、修改、复核与协调投入另计，记录实际动作和计时范围，未测得的人工成本明确留空。

如实记录由谁复核、是否为 Agent、是否参与生成或修复，以及看过哪些材料。Agent 核对和熟悉材料的开发者操作不能替代独立真人验收或新用户体验。没有相应证据时，不填写真人 Gold、盲测通过或普遍准确率。

原文、知识全文、完整模型返回与私人路径只提供给获准的复核者。公开讨论保留必要的脱敏问题、机制、处置与证据索引，避免公开可识别的私人材料。

## 6. 决定可用、继续还是停止 {#decision}

| 决定 | 依据与下一步 |
|---|---|
| 在声明范围内使用 | 预先要求的知识已核对，影响判断的错误已处理，剩余修改负担在约定范围内；保留适用条件、未知和未完成的独立验收限制。 |
| 继续修复 | 已找到可追溯的遗漏或错误机制；保存原失败，修订知识或提出实现改动，以新身份和相称范围复验，不把人工改好后的结果算成原提炼成功。 |
| 停止扩大 | 来源不足、关键分歧未解决、结果或派发状态未知，或错误与纠错成本超出用途可接受范围；先补证据或明确处置。未知派发只核对、恢复已有状态，不盲目重发。 |

这些判断描述选定材料与当前用途，不自动形成总体质量或任务收益结论。真实材料的开发核对与改进记录由 [#1388](https://github.com/lizhiyao/oh-my-knowledge/issues/1388) 承载；需要核对历史冻结研究时，使用[研究证据核对指南](verify-extraction-study.md)，保留其原测量身份与限制。
