### 已观察到的目标行为

两个计数窗口都保留 Session；一个另建初始化／状态更新操作概念，另一个直接表达为 Session 陈述。来源明确区分操作时，v8 允许合理独立粒度；对象数量不是质量判据。较早窗口保持未核实状态，较晚窗口才有 API／页面口径的解释。没有从数量或一个 SID 虚构具体实例。

两处计数规则分别形成正向初始化与否定状态更新的陈述，没有重复旧 v6 较晚输出的正负混合问题。代码窗口区分具体方法、字段、版本和返回值，保留局部回归、未见修复结果及“迟到错误不能污染新 Session”的约束；没有把全部 protected 覆写概括为错误。

这些是当前输出的逐项观察。来源是助手自述，工具结果不在窗口，不能把引用链接或“核验通过”的来源说法当作独立事实证明。旧 v6 的 28／31、39／40 和 v7 的 20／22 不重算，也不据本批推断提示词因果收益。

### 层次争议、语气与知识覆盖缺口

master 与已发布 beta.2 被独立比较，输出把前者作为未发布开发版本，并保留提交未知；作者认为 version 有合理代码状态解释。不过输出前标准仅列 object，因此保留一项层次不符。后续若允许多个合理层次，应先裁决再冻结新标准；不能在看到输出后扩充当前答案宣布通过。

较晚窗口的 `p2/s5` 将“无需修改 SDK”写为 `modality: normative`、`polarity: negative`、基础谓词“为本次 Session 显示计数差异进行修改”。项目规则中这种组合表达负向要求，容易读成“不应修改”，而来源只否定修改的必要性。虽然 context 保留来源判断，仍不能替代命题字段中的必要性范围。记录一项语气强化的知识语义问题，不能因陈述已原子拆开、结构可接纳就忽略。

`_unhandledSessionStatus` 的字段身份和原文位置保留，但其配置值 `unhandled` 没有在派生实体限定或知识陈述中出现。本窗口冻结标准要求保留值与字段／拥有者的关联，因此记录一项知识覆盖缺口。原文仍可追溯，这不是字段实体遗漏，也不要求该值独立建实体；实体提取允许少量甚至空知识，不将每个未生成的来源事实都判为错误。后续须明确这类独立讨论配置点的关联知识保留范围。

## 应用链重放

仅用本轮已有输出，在当前生产应用的隔离知识目录捕获原脱敏消息、提炼和落盘，新增外部模型调用 **0**。只将 evidenceRef 一一绑定新快照，消息、角色、时间、序号与原输出保留；应用正常分配新的持久身份，映射、原／重绑定摘要及两种覆盖限制另存，不冒用原模型运行身份。

重新打开文件存储后，41 个实体、50 个提及、7 个候选、19 条陈述及所有引用载荷与原接纳结果一致，包括 core 版本的组件关联。全部实体可检索、提及可定位、知识绑定明确实体修订。该结果证明应用接线与落盘保留，不弥补层次不符或缺失配置值；知识未因此标为用户保留。本轮不重验 Chrome 纠正／历史、合并／拆分或四泳道报告，界面证据复用未变化的[已有输出动线验收](./entity-extraction-v8-workflow.md)。

## 限制与后续

仅单轮、3 个软件窗口、一组来源，并且有前后重叠，不能外推广域实体、长会话、跨 Agent 复用或总体稳定性。所有窗口早已在 v6 查看，不是盲测、独立或代表性样本。选定窗口排除工具、系统和周围上下文；源记录另有 24 条解析失败，完整性未知。脱敏后位置针对脱敏文本。

后端模型修订、seed、采样参数和默认推理强度未固定或实报。43 个合成窗口／147 关键提及仍未验收；本批也没有测试旧真实样本中的 Memory 含糊指代或第三个 Session 遗漏窗口，不把两处观察概括成所有旧问题已修复。
