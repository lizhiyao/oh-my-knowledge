### 核心对象遗漏

Session 的统计、状态更新、归属适配可以是独立对象，但不能替代窗口明确讨论的 Session 概念。3 处遗漏来自相关软件会话，其中两个窗口有消息重叠；这是可复现的诊断方向，不是三个独立总体样本。后续应明确“核心概念与其属性、过程分别识别”的规则和正反例，同时避免把每个复合词拆成无用实体。

### 指代歧义

历史产品窗口明确出现多个可能含义，用户没有进一步消歧。模型在 rationale 中说明最终回答对象及未获用户确认，但仍将最初提及结构化绑定为单一身份。该判断有上下文推断依据，不能称为凭空编造；问题是解释中的不确定性没有落实到实体身份／候选字段。助手选择怎样回答，不能自动确证用户最初所指。

### 陈述与否定范围

补充证据后的窗口将一项正向规范与一项否定规范放在同一 relation 中，只设置一个 negative polarity。上下文说明否定仅作用于后一部分，但结构字段无法清晰表达两个命题。作者判为需要拆成两条陈述；不据此宣称来源事实已被证明反转。较早窗口已分成两条，不能因它正确而覆盖较晚输出的问题。

### 层次标注争议

库、本地 Memory 功能和 master 共 3 项分别输出 component、component、version，冻结预期仅允许 object。原文持续讨论实现功能或将代码状态与发布版本对照，作者认为存在合理建模解释，未将这 3 项一律判为确定语义错误；但冻结检查的不符仍保留。下一次冻结前应裁决合理备选，不能输出后改答案改善本次计数。

## 覆盖限制与后续

样本主要来自软件工作，复用已查看历史知识输出的材料；不是盲测或真实日志代表样本。仅选定消息进入模型，工具、系统及周围未选记录均排除；另有 24 条源记录无法解析，整体来源完整性未知。脱敏会改变字符串，所有定位针对脱敏文本；来源断言不等于事实已独立核实，历史产品说法不作为当前官方能力结论。

只有单轮小批采集，后端模型修订、seed、采样参数和默认推理强度未固定或实报。不能据此推断总体稳定性、提示词因果收益、长会话效果或跨 Agent 复用收益。已查看的窗口后续只能作开发回归；此前合成集 39／40 使用不同单位，保持原记录，不合并重算。
