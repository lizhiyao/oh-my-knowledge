# 实体提取 v3：观测结果与限制

最新的[16 场景两轮验收](./entity-extraction-repeat-quality.md)发现了重复的提及失败及环境身份范围问题。本文保留 2026-10-09 的原始 v2／v3 对照，不用新语料重算历史结果。

本轮小规模合成语料支持的结论是：新版提供独立实体结果，提及记录更精确。它**尚不能证明知识中的对象错误减少、真实日志提取可靠或跨 Agent 复用有效**。一处对象粒度问题仍待裁决。本文记录已完成的对照，不是发布质量认证。

## 证据与复核范围

2026-10-09 UTC，`knowledge-extraction-v2` 与 `knowledge-extraction-v3` 各对相同的 12 个合成窗口运行一次，使用现有 Codex 执行器和 `gpt-6.1-sol`：共 24 次调用，无自动重试。语料、38 处关键提及位置、20 个重要局部对象、必须分开的身份、未消解指代及角色复核标准均在输出前冻结。复核标准不发送给模型。两版逐例输入摘要一致。

## 观测到的对照

两版均完成 12 次调用，没有结构拒绝。执行器没有报告工具调用。结构接纳证明位置与引用合法，不证明身份正确或陈述为真。

| 观测项 | v2 | v3 |
|---|---:|---:|
| 返回实体 | 12 | 22 |
| 返回提及 | 15 | 42 |
| 知识候选 | 7 | 7 |
| 精确匹配关键位置 | 3 / 38 | 33 / 38 |
| 被某段引用包含的关键位置 | 24 / 38 | 38 / 38 |
| Agent 复核中明确表示的重要对象 | 12 / 20 | 19 / 20，另 1 个待裁决 |
| 实体／知识结构拒绝 | 0 / 0 | 0 / 0 |

位置计数**不是语义准确率**。整句引用可能包含多个名字，却没有分别对应每处提及；较长的项目限定名称也可能是有效提及，即使不同于冻结的短片段。v3 的五处非精确匹配包括两处带项目限定的 Atlas、两处“实例 T／P”和“BuildKit 日志”；只有最后一处的对象粒度仍待裁决。

v2 的目录缺少八个重要对象：纠正场景中的 Cache、仅实体场景的两个名字、歧义场景的 Queue／Cache／未知对象、缺上下文的未知对象，以及 BuildKit。v2 实体附属于知识候选，因此零候选也丢失实体结果。v3 将两类结果独立保存。这项架构变化解释了部分覆盖差异，不能据此声称模型本身变强。

|---|---:|---:|---|
| `alias-pronouns` | 0 / 4 | 4 / 4 | 两版均将全称、简称和代词对应到构建器，并保留仅测试环境及生产未验证的限制。v3 分开记录四处提及；额外的缓存对象与两处提及有原文支持。 |
| `homonyms` | 0 / 2 | 0 / 2 | 两版均区分项目限定的 Atlas 服务。较长限定名称有效，裸名零精确匹配不是语义失败。 |

在明确复核的 v3 对象中，未观测到身份误合并或擅自消解。这项小规模自审结果不是精确率估计。在七个可比较的知识生成窗口中，按冻结标准复核，两版均未发现主体／对象错误。因此，**知识中的对象错误减少尚未成立**。可选遗漏不自动算角色错误；歧义场景零候选也使未知主体的后续知识生成未被模型输出验证。包含攻击文本的案例不构成普遍的提示词注入防护或文件系统隔离保证。

案例短、为合成内容，由实现 Agent 选择。它们不覆盖真实日志分布、长对话、经独立裁决的对象粒度、跨日志关联、跨 Agent 复用、多次运行稳定性、陈述真实性或载体效果。下一份质量证据应来自语料的独立裁决及另外获授权的真实日志样本。当前功能允许用户核对与纠正，但可操作性不能替代语义验证。
