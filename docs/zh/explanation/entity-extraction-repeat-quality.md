# 实体提取 v3：两轮验收未通过

当前版本**尚未满足本轮冻结的实体验收标准，仍需要用户核对与纠正**。32 次调用均捕获到可解析输出，但 6 份输出发生结构拒绝；另 2 份结构通过，却把冻结标准要求分开的环境身份归并。集合指代和重复名称定位的失败两轮均出现，不能据此支持无需核对的自动沉淀。

本轮没有修改提示词、接纳规则或存储契约，也没有用重试覆盖失败。这是合成窗口的自行复核结果，不是独立人工验收或真实日志准确率。

## 优先修正的问题

1. **环境实例身份。** 跨轮场景两轮都把未限定、测试和生产 Quartz 对应到 `e2`，三项分离及初始未知身份要求全部失败。陈述仍在 context 或环境 object 中区分测试成功、生产报错、修复未验证；不能夸大为文本把生产状态写成成功。输出采用抽象组件粒度，冻结标准要求实例粒度。产品规范需要明确两者及其关系，并独立裁决；按本轮标准仍须分开身份。
2. **集合指代的唯一位置。** 环境场景两轮及第二轮同名场景将同一“它们”或“这”位置复制给两个对象。接纳器拒绝这些重复提及，引用它们的整条候选随后被拒绝。第二轮仅实体场景将“它们”表示为一个集合对象则合法，说明处理策略仍不一致；修正不能靠放宽重复位置校验。
3. **重复名称的连续上下文。** Echo 两轮均为第二个名字填写 `suffix: "，后者"`，实际紧邻原文为“，前者”。这是引用构造错误，程序 `quote_mismatch` 拒绝正确；原始主体／对象判断合理不能补回已丢失的名称提及。
4. **案例组织与 modality。** 第一轮计划／执行场景把 normative 的 `s1` 放入 `actionStatementIds`，当前契约只允许案例行动／结果引用 descriptive 陈述，整条候选被拒绝。第二轮通过不消除第一轮失败。提示词／输出约束需在显式版本化后对齐，而非放宽接纳规则隐藏错误。

## 检查程序和复核的限制

冻结的关键词角色检查两轮各有 4 项 `matched`、1 项 `mismatched`、3 项 `not_observed`。唯一 `mismatched` 是简称场景：标准要求不带 object，实际陈述合理引用有来源支持的缓存或生产环境对象，自行复核未认定角色错误。冻结结果保留，不能输出后改答案来提高计数。

三项 `not_observed` 来自歧义、缺上下文和 Echo 场景没有可选知识候选；不能算角色错误，也不能证明相应角色生成可靠。关键词、字符覆盖和合法引用均不能代替逐项语义复核。额外实体逐一核对了原文，但没有独立评委或人工裁决。
