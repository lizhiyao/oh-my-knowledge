# OMK 如何理解知识

**知识是用完整自然语言正文段落表达、值得未来复用的认识、案例、方法或约束；实体把知识关联到它讨论的事物。**

正文是主数据。每段有稳定的 `segmentId`，独立保留理解它所需的条件、归因、否定、例外、时间、参与者立场与未知。标题、引文、实体目录或复用理由不能补齐正文遗漏的含义。`fact`、`case`、`method` 只是组织类型，不是可信度等级。

Inline evidence 保存精确来源 snapshot／version、连续原文、宿主核对的 UTF-16 位置，以及 `source_assertion`、`direct_observation` 或 `inference` 依据类型。定位成功只证明位置，不证明真值或完整来源保真。来源时间不自动等于事实时间。保留／舍弃决定绑定精确正文修订，新修订仍待审。

实体可以是实物、人、文件、系统、概念或计划。只有来源语境能支持其含义：苹果可能指水果或公司，键盘可以指类别或某把具体设备。名称、路径和相似度不证明同一对象；`description`、`qualifiers`、指代层次与明确不确定性保留这些区别。

实体关联与可选 typed 关系是绑定 `{knowledgeId, revisionId, bodyDigest}` 的**独立派生投影**，有各自的修订和审查决定。生成先保存正文，再尝试这些投影；投影失败、分歧、纠正或重建不删除、不改写正文。主体／关系／对象可以表达某项关联，但不是全部知识的强制正文形式。

任务检索在可调响应预算内选择完整正文段及其证据。默认 **65536 UTF-8 字节包含整个 JSON 响应与换行**，仍支持显式 8192。这不是知识定义、存储硬上限或模型上下文限制。完整段落装不下时明确整段省略，不截断条件。字面检索不等于语义检索，增大初始预算本身不证明任务覆盖完整。

prompt、skill、agent、workflow 等是知识载体。观测提供真实工作证据，受控评测检验具体载体改动是否帮助任务；保存、保留与审查本身不证明收益。[实体知识库](../specs/knowledge/knowledge-library.md)通过明确人工确认组织窗口身份，不自动跨 Agent 归并。身份交接、版本边界与迁移见[知识建设与维护契约](../specs/knowledge/knowledge-domain-model.md)。
