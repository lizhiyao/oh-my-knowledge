# OMK 如何理解知识

**实体是知识所描述的事物；知识表达实体在特定上下文中的状态、关系或行为。**

实体提取首先识别对话谈到的事物与概念，例如苹果、OMK、键盘、保险、Node；再结合语境归并名称与指代、保留歧义，并关联关于它们的知识。普通实物和抽象概念都属于范围，不局限于人名、地名、机构名或软件组件，也不以穷举所有名词为目标。

苹果可能指水果或公司，键盘可以指一类物品或某把具体键盘，保险可以指领域概念或某个产品；只有来源语境支持时才能确定含义或建立关联。语义类别与 `referentKind` 的指代层次是不同维度：当前用有来源的 `description` 解释对象含义，`qualifiers` 保存所属人、用途、领域、项目等限定，不新增强制类别体系或存储字段。组件、实例、版本与集合仍按来源需要保留。

**知识的表达形式：**

> **时间范围＋场景＋条件＋实体 A＋关系或行为＋实体 B（如有）**

在这条表达中，A 扮演主体，B 扮演对象；换一条表达，角色可以交换。

- **实体不一定是物理存在。** 人、文件、系统可以是实体，规则、概念、计划也可以被建模为实体。
- **知识可以关联多个实体，不必只归属于 A。** 「模块 A 依赖模块 B」既是关于 A 的知识，也是关于 B 的知识，可以从任一实体检索到它。

这个公式描述知识的基本表达结构。事实知识可以用一条陈述表达，案例知识和方法知识通常由多条陈述组织而成。prompt、skill、agent、workflow 等是承载知识的载体。观测提供真实工作中的知识证据，评测检验具体知识载体改动是否改善任务表现。

现有实体目录支持窗口内对象、原文提及和关联知识的检索与核对；跨日志统一身份、跨 Agent 关联和复用收益仍待实现与验证。对象关系与数据结构见[知识建设领域模型（设计草案）](../specs/knowledge-domain-model.md)。
