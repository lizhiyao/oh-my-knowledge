# 实体提取 v4：两轮结果与限制

**两轮验收和 Agent 逐例自审已完成，冻结回归门槛未通过。** 32 次调用均取得可接纳输出，但每轮仅命中 45／50 个冻结关键提及，各有 9 个身份提及对无法程序判断；实体层次仍有过度判断。自审还发现共同指代归属问题和一处知识否定表达歧义。当前证据不能支持“实体提取已经做扎实”。

本报告使用修正后的合成语料 v4、指南 v2、检查 v2，以及生产 `knowledge-extraction-v4`／响应 Schema v4。它不修改提示词、答案、门槛、用户存储或[历史报告](./entity-extraction-repeat-quality.md)，也不重新计算旧分数。

## 冻结证据与执行范围

每轮的 5 处严格遗漏都来自相同的两个窗口：`dev-unresolved` 使用“西区对象 W”“东区对象 E”，`dev-replacement` 使用“旧 config.json”“另一个 config.json”“新 config.json”。自审判断这些完整描述短语的对象归属合理；它们没有进入输出前冻结的允许边界，故原始遗漏和 `not_evaluable` 保持不变。不能把它们全部说成实体缺失，也不能事后补答案改成 100%。

## 逐例自审与发现

已对 32 份输出中的实体、额外提及和 22 个生成知识候选逐项检查来源、身份、角色、否定、条件、时间及来源说法／直接观测。6 份输出有实体语义问题，另有 1 份知识候选存在极性歧义，共 7 份需要处理。其余输出在本次自审范围内未发现问题；这个数不是独立语义准确率。

| 场景 | 两轮自审结论 |
|---|---|
| `dev-rename` | 改名前后及代词为同一文件；额外操作约定对象有依据。文件保存内容的双端陈述合理，程序端点待复核不自动判错。 |
| `dev-environment` | Rill 的环境条件和未验证修复保留正确；两轮都将 Pavo 无依据地称为系统并标 `component`，未保留层次不确定性。 |
| `dev-instances` | 明确实例分开并关联 Sieve；通过／失败分别归到各实例，没有推广到整个组件。 |
| `dev-collective` | 集合完整且提及只绑定一次；第一轮知识保留总数 3，第二轮不生成可选知识。未把总数分配到个体。 |
| `dev-unresolved` | 两个对象分开，报错代词保留两个候选；较长边界合理，严格检查仍未命中。 |
| `dev-repeated-code` | 三次名称逐次定位并归到同一命令；两轮没有可选知识。 |
| `dev-plan-run` | 计划、演练和生产发布分开；完成演练不等于验证通过或发布完成。fact／case 两种组织均有来源依据。 |
| `dev-replacement` | 同路径删除重建仍为两个身份；能力正负归属正确，操作未冒充已执行；边界差异不改分。 |
| `val-rename` | 改名保持身份，清单是额外内容对象；未补造内容变化或工具验证。 |
| `val-environment` | 环境作为条件，修复仍是建议；没有认定已执行或成功。 |
| `val-versions` | 组件与两个归档版本分开并关联；不可变性仍为用户说法。 |
| `val-partial-members` | 两轮均保留部分成员和缺口；第二轮把 Cedrus、Dahlia 从普通检查节点推定为 `instance`，来源未明确部署实例。 |
| `val-truncated` | 主体未消解且无候选，不补造窗口外身份；两轮没有可选知识，未覆盖未消解主体的知识生成。 |
| `val-namespaces` | 文件身份分开。第一轮知识 s2 的关系已写“不要合并”，又标 `negative`，有极性解释歧义；第二轮额外 m3 将共同属性“their basenames”只归到 repo-a 文件，丢失共同指代。该知识没有引用 m3。 |
| `val-late-correction` | 更正及早期相反说法被保留，归因未提升为已验证根因；两轮均无依据地把 Flint、Garnet 标 `component`。额外故障事件层次没有独立裁决。 |
| `val-tool-log` | 写入者和日志分开；第一轮下次覆盖仍是未来且未发生，第二轮没有可选知识。 |

8 个程序身份不匹配项均为 `referentKind`：Pavo 两轮各 1 个，Flint／Garnet 两轮各 2 个，Cedrus／Dahlia 第二轮 2 个。来源的实际对象类型未必已知；问题是直接给出更具体层次，却没有足够来源或不确定性。第二轮的共同属性归属问题发生在冻结关键提及之外，所以程序全命中仍漏掉它。否定表达歧义登记为待修复的可解释性问题，不断言已经证实输出了相反知识。

自审未发现生成知识将环境结果推广为普遍结论、把计划写成完成、补造时间或把用户说法升级为直接观测。22 个候选中仍有上述 1 个极性歧义。可选知识允许省略，第二轮少生成集合／日志知识不自动算错，但下游关联覆盖减少。原始程序结果中的 `semanticReview: pending` 未被改写；完成的是独立保存的 `agentReview`。

## 后续工作与复现

优先处理来源不足时的保守层次、共同指代与属性跨度、否定关系和极性的单一表达。合理但未列入的描述边界需要先裁决并冻结新版本，不能回头重算这次结果。验证窗口已被查看，不再用它们调参后声称盲测收益；后续改善证据需另定未用于调参的窗口。

[标注指南](../specs/entity-extraction-evaluation.md)定义未通过的原始门槛及离线工具。公开证据中的两份 `captures` 可分别导出到仓库外，以冻结构建和同一语料运行离线复核；命令本身不调用模型。重建若改变编译产物摘要，应保存为新的测量身份，不能冒用本报告的身份。

本次运行包保留冻结构建信息、完整执行器结果、失败记录、自审和脚本；公开证据可校验输入／输出摘要、重新接纳及执行严格检查。运行授权和成本范围止于已完成的 32 次调用。本次交付不宣称独立质量验收完成，[Issue #1127](https://github.com/lizhiyao/oh-my-knowledge/issues/1127) 的独立复核仍待完成。
