# 带 npm 依赖的多文件任务

[English](./README.md)

购物车项目的 `src/cart.mjs` 导入本地 npm 包 `@task/money`。缺陷是折扣在计税后才扣除。独立验收覆盖折扣、数量、无折扣、无税、舍入与空购物车六项要求；验收程序不进入 Agent 快照。

## 运行

先把本目录复制到临时目录，再执行：

```bash
cd /absolute/path/to/copied/project/snapshot
npm ci --offline --install-links --ignore-scripts --no-audit --no-fund
cd ..
omk eval task task.yaml --dry-run
omk eval task task.yaml --output /absolute/path/to/reports
```

本地依赖不访问 registry，不需要模型或凭证。`--install-links` 将本地包安装为实际文件；默认符号链接会被快照校验拒绝。锁文件、应用代码和安装后的依赖文件均显式列入快照及产物清单，因此 Agent 与独立验收加载相同版本。不要把整个 `node_modules` 或用户配置目录纳入快照。

默认 fixture 只验证接线：control 不修改，treatment 修复。真实 Agent 按[上层示例](../README.zh.md#真实-codex-试跑)替换 execution，模型与 effort 显式固定；运行前查看成本未知及可信本地执行边界。

## 接入成本

从已有项目接入的手工步骤：确认独立验收要求；编写验收程序；选择两个知识版本；填写任务定义中的文件清单与执行配置；在复制的项目安装锁定依赖；预览并运行。本例应用有一份源码、一个本地依赖包，以及 package／lock 文件，独立验收包含六项检查。

需要自写的集成代码只有领域验收程序；真实 Codex 路径无需自写 executor、隔离目录、产物采集或清理逻辑。fixture 是离线回归测试代码，不是用户必须编写的接入层。需要新增文件时仍须手动扩充快照与采集清单，外部依赖的安装、许可证和来源仍由作者负责。

## 证据边界

这是一个包含真实 npm 安装与跨文件导入的小项目，不是生产业务仓库，也没有第三方网络依赖。它证明这一规模下的接入可行性，不代表复杂项目的一般接入耗时或统计显著性。
